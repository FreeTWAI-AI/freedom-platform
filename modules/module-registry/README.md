# Module registry

The registry is the launch engine for offered applications. It owns application and module definitions, guild offerings, installations, module instances, deployment bindings, workspace entry bindings, launch plans, provision operations, and capacity reservations. It does not own Work rows or Result bytes.

`enableManualWork` is a facade over the same plan and launch core. The wire stays a `ManualWorkBinding`. An already-bound workspace returns inside the command with `reused: true` and writes no new domain rows. A missing capacity policy is still `policy_unconfigured` on that path. When the tenant already has an active `work` instance and the caller sends no choice, the command fails with `instance_selection_required` even if there is exactly one candidate. The workspace row is locked `FOR NO KEY UPDATE` inside launch, after the installation fingerprint and the policy advisory, not in authorize.

First-party pins live in `definitions.ts`. `manual-workspace@1.0.0` requires `work@1.0.0`. The work `contract_ref` is pinned, including `behavior_profile` `freedom.tenant-work/v1`. That profile contains a slash, so it is not a StableKey; the SQL shape check allows it. There is no HTTP endpoint that creates or edits definitions or offerings.

Capacity limits are read from `tenant_capacity_policies`. No migration seeds a row. A missing active row rejects enablement and launch with `policy_unconfigured`. A limit of 0 is `quota_exceeded`. Reused instances reserve nothing. Pure `reuse_existing` does not reserve `concurrent_provisions`.

The hosted work provider is transactional and runs inside the launch transaction. Its initialiser lives in this module so the registry does not import a downstream work service. Async providers run only after commit. The worker sweep uses the default provider map. One poison operation is logged as `module_provision_sweep_operation_failed` plus a Problem code or error name and does not stop the rest of that sweep.

Leases, `next_attempt_at`, retry backoff and plan expiry all use `clock_timestamp()`. A test may pass a clock; that value is the timestamptz those statements use. The sweep's process budget stays on the JavaScript clock.

Lock order. `FOR NO KEY UPDATE` on the workspace does not conflict with the `FOR KEY SHARE` an installation or plan insert takes through the workspace foreign key, so `lockWorkspace` stays after those inserts and after the policy advisory. The only workspace row locks on these paths are that foreign-key `FOR KEY SHARE` and `lockWorkspace`'s `FOR NO KEY UPDATE`. No path takes a workspace row lock that conflicts with `FOR KEY SHARE`. A workspace `FOR UPDATE` cycles in either position: before the policy advisory it cycles with Work create, which takes that advisory and then the work-row insert's key share; after the advisory it cycles with launch, which takes the installation insert's key share and then the advisory.

- Launch: tenant share and tenant-membership share, plan `FOR UPDATE`, installation fingerprint advisory, capacity policy advisory `tenant.capacity/v1/<tenant>/policy` plus the policy row `FOR SHARE` plus dimension advisories in sorted order, reused instances `FOR SHARE` in UUID order, workspace `FOR NO KEY UPDATE`, then guild membership `FOR SHARE`. The guild lock is the last wait. It is not held across the earlier waits.
- Enable: tenant and tenant-membership share, unlocked policy read (a missing policy is `policy_unconfigured` before membership), unlocked guild check, guild membership `FOR SHARE` immediately before an already-bound return, installation fingerprint, the same guild lock before a binding that appeared after that fingerprint. The creating path then inserts the plan. That insert takes `FOR KEY SHARE` on the workspace. `createPlan` defers its membership lock. Launch then runs as above. Two first enables of one workspace serialize on the installation fingerprint advisory. The loser returns the committed binding and does not create a second instance. Reuse takes the instance `FOR SHARE` after the capacity policy and before the workspace `FOR NO KEY UPDATE`.
- Executor: peek the tenant, tenant share, tenant-membership share, operation `FOR UPDATE`, due step `FOR UPDATE SKIP LOCKED`. No member session and no `lockTenantScope`.
- Cancel: tenant and tenant-membership share, operation `FOR UPDATE`, re-read and check If-Match on the locked row. Once `cancel_requested_at` is set, executor, sweep and reconcile settle `cancelled` through `settleCancelled` as soon as no step is `dispatched` or `unknown`; step outcomes cannot finish it `succeeded` or `failed`. The authorization-gate `capability_denied` failure keeps precedence. Settlement archives pending steps and releases only their units, consumes the remaining reservations once, and releases `concurrent_provisions`. Confirmed instances stay active and retained, including when another step fails; the failed step keeps the existing member-data retention or archive/release handling. The installation never becomes active and no entry binding is created. Cancel does not lock the workspace.
- Reconcile: phase 1 is tenant share, If-Match, and a list of `unknown` steps, with no operation lock. A matching terminal state returns that operation and does not open a write command; the route answers 202. A stale If-Match is 412. Cancel of a terminal operation stays 409 `operation_not_cancellable`. Phase 2 locks the operation `FOR UPDATE`, re-reads the version, locks each step `FOR UPDATE`, skips a step that is no longer `unknown`, and bumps the operation version on the transition. Resolving the last open effect of an accepted cancel settles `cancelled` in that transaction, whether lookup confirms the effect or proves it absent; an unknown effect still holds quota until resolved.

Guild full membership gates enablement only. The caller needs an active `member_tier='full'` row for the named catalog key in the tenant's community. Any full guild qualifies. Interns do not. On the path that creates an instance, enable takes that membership row `FOR SHARE` after the capacity-policy lock and the workspace `FOR NO KEY UPDATE`, so a demotion that commits during those waits cannot create an instance, binding, reservation, receipt or journal row. The membership share is not taken before the plan insert. A workspace `FOR UPDATE` holder stops that insert's foreign-key `FOR KEY SHARE`. Work commands do not repeat the guild check. A later tier change does not delete or suspend Work that already exists.

Requirement order is the dependency convention. The last requirement is the caller. Each earlier requirement is a provider, and the dependency capability is that provider's first capability. A provider requirement with no capability is `application_not_available` when the definition is loaded. The entry binding is the requirement whose capabilities include `entry_capability`, not a hard-coded `work:create`. `work:create` still has to bind a `work` instance.

Module resolution uses the requirement's `module_release_ref`. That pin is stored in `module_requirements` and removed before the public requirement schema. A missing pin is `application_not_available`. There is no fallback to the highest `version` row.

Reuse accepts only an `active` instance, and only an active deployment when the instance has any deployment row. On plan and launch, anything else on an explicit reuse or a launch-time reuse lock is 409 `instance_unavailable` (this code is not in the original spec list). On the manual-work endpoint, a non-active instance or a non-`work` instance is 404 `not_found`, including a status that changes while an earlier lock is held. An inactive deployment on that endpoint stays 409 `instance_unavailable`. Default selection skips non-active instances. Changing a membership later does not suspend instances that already exist.

Owners and admins may suspend an active instance with a reason and resume a member suspension. These synchronous commands return a succeeded registry Operation at version 1, without `resource_ref`. Its ETag is the operation version; the next lifecycle `If-Match` comes from `InstanceView.version`, not that ETag. Read the instance detail for the retained member reason and bounded consumer/workspace impact. Platform holds have no suspension operation and cannot be resumed by a member. A mismatched current deployment also refuses resume. Active consumers do not prevent suspend and are not cascaded.

Suspend and resume keep all data, installations, dependencies, workspace bindings, capacity reservations and ledger rows. Application installation status and `authority_epoch` do not change. Work reads and archive remain allowed; new Work/Result writes require an active instance and current deployment. Lifecycle operations have no provision steps and never count toward `concurrent_provisions` or run through the executor/sweep. Reconcile returns their terminal operation with a matching version; cancel is `operation_not_cancellable`.

Lifecycle domain errors are `instance_not_active`, `instance_not_suspended`, `instance_security_hold` and `operation_pending` (409). Resume also requires an active capacity policy (`policy_unconfigured`, 403) and re-checks tenant and per-module instance limits (`quota_exceeded`, 429, with the dimension). Suspended instances already count, so usage equal to the limit is legal; usage above a lowered limit (including 0) refuses resume without writes. Resume uses the unlocked policy snapshot and adds no policy or dimension advisory: it changes no counted usage and cannot oversubscribe a concurrent launch. Both require current owner/admin (`capability_denied`, 403), a valid Idempotency-Key and the instance If-Match. Receipt replays re-check that capability. Guild full membership gates launch, not lifecycle commands.

## Lock table

Modes below are the locks a path takes when it touches two or more of these resources. Advisory locks are `pg_advisory_xact_lock` (exclusive for the transaction). An immediate foreign key takes `FOR KEY SHARE` on the referenced row at insert. `FOR NO KEY UPDATE` does not conflict with `FOR KEY SHARE`. `FOR UPDATE` does. The only workspace row locks on these paths are that foreign-key `FOR KEY SHARE` and `lockWorkspace`'s `FOR NO KEY UPDATE`, which comes after the policy advisory. No path takes a workspace row lock that conflicts with `FOR KEY SHARE`. Member suspend, resume and owner archive commands are available. Cancel and the executor update an instance's status, which locks that row `FOR NO KEY UPDATE`. Product code has no `UPDATE workspaces`. `modules/tenant-workspaces/` inserts a new workspace and does not lock an existing one.

| Path | Order |
| --- | --- |
| Launch | Tenant `FOR SHARE`, tenant membership `FOR SHARE`, plan `FOR UPDATE`, installation fingerprint advisory, installation insert (`FOR KEY SHARE` on the workspace, `launch.ts` 154–161), policy advisory `tenant.capacity/v1/<tenant>/policy`, policy row `FOR SHARE`, dimension advisories `module-registry/capacity/v1/<tenant>/<dimension>` in sorted order, reused instances `FOR SHARE` in UUID order, workspace `FOR NO KEY UPDATE` (`launch.ts` 181), guild membership `FOR SHARE`. After the policy advisory the instance insert takes `FOR KEY SHARE` on `module_definitions` and `application_definitions` (`launch.ts` 206). The binding insert takes `FOR KEY SHARE` on the workspace and the instance (`launch.ts` 329, after `lockWorkspace`). The plan-consumption insert takes `FOR KEY SHARE` on the plan and the operation (`launch.ts` 253). |
| Plan | Tenant `FOR SHARE`, tenant membership `FOR SHARE`, plan insert (`FOR KEY SHARE` on the workspace and on `application_definitions`, `plans.ts` 266), guild membership `FOR SHARE`. No policy advisory. The manual facade defers that guild share. |
| Manual enable | Tenant `FOR SHARE`, tenant membership `FOR SHARE`, installation fingerprint advisory (`service.ts` 84), plan insert (`FOR KEY SHARE` on the workspace and on `application_definitions`), then the launch order. An already-bound return takes guild membership `FOR SHARE` and does not insert a plan. |
| Suspend | Tenant `FOR SHARE`, tenant membership `FOR SHARE`, receipt advisory, instance `FOR NO KEY UPDATE`, current deployment binding `FOR NO KEY UPDATE`, unlocked unfinished-launch read, operation insert (`FOR KEY SHARE` on the tenant, actor principal and already-held instance), instance and binding updates, journal and outbox inserts, receipt. No capacity advisory. |
| Resume | Tenant `FOR SHARE`, tenant membership `FOR SHARE`, receipt advisory, unlocked capacity-policy read, instance `FOR NO KEY UPDATE`, current deployment binding `FOR NO KEY UPDATE`, tenant and per-module usage reads checked against the policy snapshot, operation insert (`FOR KEY SHARE` on the tenant, actor principal and already-held instance), instance and binding updates, journal and outbox inserts, receipt. No policy or dimension advisory: the suspended instance already counts, so resume adds no usage; limits are still re-checked with `usage > limit`. |
| Archive | Tenant `FOR SHARE`, tenant membership `FOR SHARE`, receipt advisory, unlocked linked-live-installation read, installation fingerprint advisories sorted by workspace UUID then application key, instance `FOR NO KEY UPDATE`, current deployment binding `FOR NO KEY UPDATE`, unlocked unfinished-launch, consumer and installation re-reads, operation insert (`FOR KEY SHARE` on the tenant, actor principal and already-held instance), instance update, binding update, installation updates in installation UUID order, journal and outbox inserts, receipt. No capacity or policy lock. |
| Cancel | Tenant `FOR SHARE`, tenant membership `FOR SHARE`, operation `FOR UPDATE`, then an instance update (`FOR NO KEY UPDATE`) for each pending step. No workspace lock and no policy advisory. |
| Reconcile | Phase 1: tenant `FOR SHARE`, tenant membership `FOR SHARE`, no operation lock. Phase 2: the same tenant locks, operation `FOR UPDATE`, each step `FOR UPDATE`. A confirmation updates the instance (`FOR NO KEY UPDATE`) and may take the workspace `FOR NO KEY UPDATE` and then a binding insert (`FOR KEY SHARE` on the workspace and the instance) when it binds the entry. Entry binding is checked before the operation terminal transition, capacity settlement, and installation update. No policy advisory. |
| Executor and sweep | Bind that operation's tenant, then peek without a row lock. Then tenant `FOR SHARE`, tenant membership `FOR SHARE`, operation `FOR UPDATE`, one due step `FOR UPDATE SKIP LOCKED`. Confirmation uses the same instance and workspace locks as reconcile. `ensureEntryBinding` takes `lockWorkspace` (`FOR NO KEY UPDATE`) and then the binding insert (`FOR KEY SHARE` on the workspace and the instance), before the operation terminal transition, capacity settlement, and installation update. It takes no installation fingerprint and no policy advisory. The sweep lists tenant scopes, binds one tenant at a time, then calls the executor once per due id. No member session. | |
| Work create | Tenant `FOR SHARE`, tenant membership `FOR SHARE`, instance `FOR SHARE`, deployment `FOR SHARE` (`tenant-work-commands.ts` 50), policy advisory and policy row `FOR SHARE` (51), dimension advisory `tenant.capacity/v1/<tenant>/work_items` (52), work-row insert (57). That insert takes `FOR KEY SHARE` on the workspace (`work_tenant_workspace`, `migrations/123_tenant_manual_work.sql` 174–175) and on the instance (`work_tenant_instance`, 172–173), and also on the resource scope and the author principal. |
| Work update | Tenant `FOR SHARE`, tenant membership `FOR SHARE`, instance `FOR SHARE`, deployment `FOR SHARE`, work row `FOR UPDATE`. No policy advisory and no new foreign-key share. |
| Work archive | Tenant `FOR SHARE`, tenant membership `FOR SHARE`, work row `FOR UPDATE`. No instance lock and no policy advisory. |
| Upload prepare | Quota advisory `asset.quota/v1/<scope>/work.tenant-result` first (`engine.ts` 140). Then instance `FOR SHARE`, deployment `FOR SHARE`, policy advisory and policy row `FOR SHARE`, work row `FOR UPDATE` (`tenant-results.ts` 83–86), dimension advisory `tenant.capacity/v1/<tenant>/retained_bytes`. After that advisory the asset insert takes `FOR KEY SHARE` on the resource scope (`engine.ts` 159), and the intent insert takes `FOR KEY SHARE` on the work row and the asset (`engine.ts` 163). Neither insert references the workspace. |
| Upload finalize | Instance `FOR SHARE`, deployment `FOR SHARE`, upload intent `FOR UPDATE`, policy advisory and policy row `FOR SHARE` (`engine.ts` 223), work row `FOR UPDATE` (`tenant-results.ts` 100–104). After that advisory the result insert takes `FOR KEY SHARE` on the work row, the upload intent, and the asset (`tenant-results.ts` 111). The result trigger also locks the work row, the intent, and the asset `FOR UPDATE` (`migrations/123_tenant_manual_work.sql` 384–391). The result row copies `workspace_id` and has no foreign key to `workspaces`. |
| Workspace create | Inserts a new `workspaces` row (`modules/tenant-workspaces/service.ts` 169 for the default workspace, 249 for a later one) and holds that new row until commit. No `FOR UPDATE`, `FOR SHARE`, or `FOR NO KEY UPDATE` on an existing workspace row. Status and list reads are unlocked. |

The registry dimension key and the Work dimension key are different strings, so those advisories do not conflict. Manual enable's plan insert and launch's installation insert take workspace `FOR KEY SHARE` before the policy advisory. `lockWorkspace` takes `FOR NO KEY UPDATE` after that advisory. `FOR NO KEY UPDATE` does not conflict with `FOR KEY SHARE`. Work create takes the same advisory and then `FOR KEY SHARE` on the workspace and the instance. That key share does not conflict with the key share enable or launch already holds, so the second arrival waits on the advisory only. Upload prepare, Work create, and upload finalize take the instance `FOR SHARE` before that policy advisory, and launch takes the policy advisory before the reused instance `FOR SHARE`. `FOR SHARE` does not conflict with `FOR SHARE`.

Anonymous `GET /api/v1/applications` stays `public, max-age=60` and sends `Vary: Cookie`, so a shared cache does not serve that response to a member on the same URL; error responses of the public catalog and release routes are `no-store`.

Lifecycle locks follow Work create, Work update, upload prepare and upload finalize: instance before current deployment. Resume reads the active policy before the instance lock, without the policy advisory. Work holds instance `FOR SHARE` then waits for that advisory; launch holds it then takes reused instances `FOR SHARE`. Adding the advisory before or after lifecycle's conflicting instance lock would close a cycle with one of these paths. Suspend/resume can wait for one launch lock, the reused instance `FOR SHARE`; after taking it, launch waits only for the workspace and the guild membership, which suspend/resume never lock, so no cycle closes. Executor/cancel/reconcile update only their own non-active step instances. Suspend checks unfinished launch steps and installation links after locking the instance: reuse's `FOR SHARE` either commits first and is seen, or waits and then refuses the now-suspended instance.

Workspace binding reads and launchpad context honour ordinary Work instance grants. Operators/viewers require a binding and `work:read` for its instance to obtain context; its instance list contains only their granted instances. Owner/admin projections and all instance-management, lifecycle, plan, launch and operation authority rules stay on their role template.

Executor and reconcile entry-binding conflicts finish directly as `failed` with `workspace_binding_conflict`. The installation never becomes active. Confirmed active instances are retained, as on the existing binding-conflict failure path; their reservations are consumed once. Consumption atomically changes only `reserved` or `unknown` reservations; already `consumed` rows do not gain another version or `actual` ledger entry.

Owners may permanently archive an active instance with an active deployment, a member-suspended instance with a suspended deployment, or a failed instance. There is no unarchive. The instance and its operations, Work, Results, dependencies and workspace bindings are retained. The deployment is retired; every linked live installation is archived and its version advances, while failed installations and other instances stay as they are. Detail retains the member archive reason/time. Cleanup by a cancelled launch or compensation is `kind: launch` with the operation ID derived from its failed-known or compensated step; its time and reason remain null because no archive metadata was recorded. An archive with no such operation is `kind: platform` with null metadata. The only event is the instance status change.

The live-consumer refusal uses `instance_has_consumers` rather than SP-04’s `dependency_in_use`, just as reuse’s `instance_unavailable` is a deliberate vocabulary deviation. Detail exposes `blocking_consumer_count` with the same live-caller predicate and lists blocking consumers first, within the 50-row bound. Total `consumer_count` still counts all retained dependency rows.

Archive domain errors (409) are `instance_archived`, `instance_not_archivable`, `instance_security_hold`, `operation_pending`, `instance_has_consumers` and `instance_changed`. Only owner has `module.instance.archive` (403 `capability_denied` otherwise); authorization and receipt revalidation both check it. Instance visibility, headers and CAS follow suspend. Live callers in requested, provisioning, active or suspended states block; failed and archived callers do not. Unfinished launches block via either steps or installation links.

Workspace bindings cannot be deleted or rebound. A bound workspace keeps its old Work readable after instance archive; new Work and Result writes return 409 `work_instance_unavailable`. Choose another workspace to create new Work. Archive frees capacity because usage counts only requested, provisioning, active and suspended instances. It takes no capacity advisory/policy lock and writes no capacity reservation or ledger. A concurrent launch that counted before archive committed may safely be refused.

The capacity ledger records each launch operation’s reservation lifecycle: reserved → consumed/released/unknown. Occupancy after launch is derived from instance status. Archive frees occupancy without a ledger row; consumed launch reservations and their historical actual entries remain unchanged. Reconciliation compares reservations with the ledger per operation, and compares current usage with instance statuses, rather than treating ledger totals as current occupancy.

`GET /api/v1/tenants/:tenant_id/workspaces/:workspace_id/module-binding` returns the retained entry binding (entry capability, instance ID, status and writability), independently of hosted connection health. It shares `launchpad-context`'s read check through one helper: `work:read` from the tenant role template or an active ordinary grant, an active workspace, and `work:read` on the bound instance; an unbound workspace is readable only by owners and admins. `writable` reflects the instance and its current deployment, not the caller's own write capability. `writable` shares the Work write predicate: the instance and its current deployment must both be active. The Work contract and `launchpad-context`, including `connection_summary`, remain unchanged because the contract artifact is pinned by `work@1.0.0`. A workspace whose bound instance is archived or suspended keeps its Work and Results readable; the portal loads both routes, hides write actions and retains read pagination. Plan and launch reject `workspace_binding_conflict` when the chosen entry instance would differ from an existing binding, including a new instance; reusing that bound instance remains valid. Launch rechecks after the workspace lock, before creating module rows or dispatching providers.

### Archive lock pair analysis

- Launch creating an installation with a reused instance shares installation fingerprints and the instance. Both acquire any shared fingerprint before the instance. A launch on a new fingerprint can commit a new link before archive locks the instance; the unlocked re-read then returns `instance_changed` without effects. If it waits for archive's instance lock, it rejects the archived instance. Archive never waits on launch's policy, workspace, guild, plan or operation locks, so no cycle closes.
- Launch `reuse_existing` shares the installation fingerprint and installation row, takes no instance lock, and serializes before archive's installation updates. Archive first makes the old plan `plan_stale`; launch first commits before archive retires that installation. No reverse lock order.
- Manual enable shares fingerprints and the reused instance on its creating path, using the same launch order. An already-bound return locks no instance/installation; bindings remain intact. Archive takes no workspace, guild or capacity lock, so no cycle closes.
- Suspend and resume share instance then deployment in the same order. They take no installation fingerprint or installation row lock, so archive's earlier fingerprints cannot complete a cycle; the stale loser gets 412.
- Work create and update share instance then deployment in the same order. Work's later policy, dimension and work-row locks are absent from archive. Its foreign-key key shares do not conflict with archive's instance `FOR NO KEY UPDATE`. One arrival waits and no cycle closes.
- Upload prepare shares instance then deployment after its quota advisory; upload finalize shares instance then deployment before intent, policy and work locks. Archive takes none of those later locks or the quota advisory, so neither pair closes a cycle.
- Executor shares an instance update, deployment and possibly installation updates. It locks its operation/step before instance; archive only reads existing operations unlocked, inserts a fresh terminal operation and never takes an existing operation/step lock. Unfinished launches are refused. Archive takes no executor workspace lock or fingerprint after instance, so no cycle closes.
- Cancel shares instance/deployment updates and possibly its installation. Its operation lock precedes those; archive never waits for that operation lock. Unfinished launches block archive and terminal launch kinds cannot be cancelled. No cycle closes.
- Reconcile shares instance/deployment and installation updates on its confirmation path, with operation/step locks first. Archive's pending reads use no row lock and its inserted operation is new. The terminal archive reconcile path is read-only. No operation/instance reverse wait closes a cycle.
