# Module registry notes

- Do not import the asset engine from this module. Capacity checks that uploads need live in `modules/opportunity-project-work/tenant-capacity.ts`.
- `capacity.ts`, `service.ts` and `lifecycle.ts` may import that capacity helper. New registry files do not import other downstream business modules. The work initialiser stays in `providers.ts`.
- Do not put a synthetic capacity inserter or synthetic module definitions in product code. Tests and the e2e server insert the disposable platform-default capacity row. The e2e server does not register synthetic providers.
- Launch lock order: tenant and tenant-membership share, plan `FOR UPDATE`, installation fingerprint advisory, installation insert (`FOR KEY SHARE` on the workspace), capacity policy advisory then policy share then sorted dimension advisories, reused instances `FOR SHARE` in UUID order, workspace `FOR NO KEY UPDATE`, then guild membership `FOR SHARE`. The launch workspace lock does not use `FOR UPDATE`, so it does not deadlock with the foreign key's `FOR KEY SHARE`. Do not take the guild lock until after the last wait on the path that creates an instance. The manual-work facade defers that guild lock inside `createPlan` and takes the installation fingerprint before the plan row exists. The creating path then inserts the plan (`FOR KEY SHARE` on the workspace) and follows the launch order. It does not take a workspace `FOR UPDATE`. Two first enables serialize on the fingerprint. The loser returns the committed binding. The only workspace row locks on these paths are the foreign-key `FOR KEY SHARE` and `lockWorkspace`'s `FOR NO KEY UPDATE` after the policy advisory.
- Reuse takes the instance `FOR SHARE` after the capacity policy and before the workspace row. Full membership is locked `FOR SHARE` only after that workspace lock on the creating path.
- The executor has no member session. It binds that operation's tenant, peeks the operation, locks the tenant and membership `FOR SHARE`, then the operation, then one due step `FOR UPDATE SKIP LOCKED`. It does not call `lockTenantScope`. A missing tenant scope fails closed.
- Cancel releases units only for pending steps, then `finishOperation` consumes the rest. Do not call `releaseAllHolding` on a partial confirmation.
- Reconcile of a terminal operation returns the current operation when If-Match matches. It does not use `operation_not_cancellable`. Phase 2 re-reads the operation version after `FOR UPDATE` and skips a step that is no longer `unknown`.
- Leases, `next_attempt_at`, backoff and plan expiry use `clock_timestamp()` unless a test clock is passed into the SQL. Sweep one operation's failure with `module_provision_sweep_operation_failed` and the error name only.
- Entry binding follows the requirement whose capabilities include `entry_capability`. Dependency direction is requirement order: last is the caller, earlier requirements are providers, and the capability is the provider's first capability. Resolve a module by `module_release_ref` on that requirement.
- Explicit reuse of a non-active instance, or one whose deployments are all inactive, is 409 `instance_unavailable` on plan and launch. The manual-work endpoint returns 404 `not_found` for a non-active instance or a non-`work` instance, including one that changes during an earlier wait. An inactive deployment on that endpoint stays 409 `instance_unavailable`. New launches re-check the guild tier after the workspace lock. Existing instances stay as they are when a membership changes later.
- Journal a new binding once, with operation `manual.work.enable`. Returning an existing binding must not write another fact at the same version.
- `contract_ref` is required on module instances. The launchpad context projection omits it and keeps the older status set.
- Guild catalog keys are validated against `positioning_guild_catalog`. There is no category column and no community column on the catalog.
- Every transaction in this module uses `isolatedTransaction`. Member commands and reads bind through `lockTenantScope`. The sweep binds one tenant scope at a time and never reads another tenant's operations in that transaction. Catalog eligibility binds the principal, then one managed tenant at a time, because installations are invisible until that tenant is bound. Do not import `transaction` from `packages/db` and do not call `pool.query(`.
- Plan `policy_revision` is the capacity policy revision. Eligibility `policy_revision` is the offering `launch_policy_ref.version`.

- Suspend/resume take tenant and membership `FOR SHARE`, receipt advisory, instance `FOR NO KEY UPDATE`, then its current deployment `FOR NO KEY UPDATE`. Resume reads the active capacity policy unlocked before the instance; neither command takes a policy/dimension advisory (it would cycle with Work or launch). Suspend checks unfinished launch steps and installation links after the instance lock. Keep the revalidate capability hook for receipt replays. Do not use `setInstance`: lifecycle keeps the deployment suspended rather than retired. Neither installation status nor authority epoch changes.

- Owner archive extends `lifecycle.ts`. Take linked installation fingerprints in workspace/application order before the instance `FOR NO KEY UPDATE`, then the current deployment. Re-read links unlocked after the instance lock; an uncovered fingerprint is `instance_changed`, never a new fingerprint lock after instance. Update linked live installations in installation UUID order. No capacity/policy lock; retain all workspace bindings, dependencies, Work/Results and history. Only archive retires its deployment; suspend keeps it suspended. Archive revalidates owner capability on receipt replay.

- `platform-hold.md` SQL blocks are executed by `tests/runtime/module-instance-lifecycle.test.ts`; change the document and its tests together.
