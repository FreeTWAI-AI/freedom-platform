# Planning contract scaffolds

> 狀態：現行 canonical baseline（2026-09-19 低維運互惠修訂）；planning 文件，不代表已部署。

這個目錄把規劃文件中的關鍵接點轉成可由工具讀取的起始 artifacts。狀態是planning specification，不是假稱已發布的production contract，也不得被production active channel直接pin。1A 契約凍結要由各domain owner補齊每個endpoint/event payload、建立fixtures，在同一個受review PR materialize唯一authoring source`freedom-platform/contracts/`並發布第一個immutable `ContractBundle`。正式PlanBundle的`contracts/`subtree只能由該exact ContractBundle release做byte-identical derived snapshot，記錄source release identity/digest；不得繼續從本scaffold目錄獨立發版或手改投影。

正式化步驟：

1. 選定contracts domain/package registry和semver policy；將現行 scaffolds 經 AI review＋verification 後搬入／補齊到root`contracts/`，發布第一個immutable ContractBundle，並關閉planning scaffold作production source的可能性。
2. 以 CI 驗證 JSON Schema、OpenAPI、YAML references 與 example fixtures。
   - OpenAPI 含相對外部 `$ref`，validator 必須使用檔案 base URI；從 repository root 執行以下 exact command（`openapi-spec-validator==0.9.0`）：

     ```bash
     python3 - <<'PY'
     from openapi_spec_validator import validate
     from openapi_spec_validator.readers import read_from_filename

     spec, base_uri = read_from_filename("docs/platform-plan/contracts/openapi-outline.yaml")
     validate(spec, base_uri=base_uri)
     print(f"PASS base_uri={base_uri} paths={len(spec['paths'])} schemas={len(spec['components']['schemas'])}")
     PY
     ```

     直接 `validate(spec)` 沒有 resolution scope，不能用來判定這份含相對外部 `$ref` 的 spec 無效；不得因此內聯或改寫現有外部 refs。
   - `entity-playbook`與`member-onboarding`的每個checklist item、status、readiness都必須帶`enforcement=navigation|action_gate`；schema與domain negative tests拒絕省略值、navigation帶gate欄、action_gate缺gate class／target action，以及四類allowlist以外值。Navigation missing／skip／stuck／connector unavailable不得產生member-facing 403、entitlement/rank mutation或discoverability降權。
   - JSON loader必須在schema validation前拒絕duplicate member names。`freedom.project.yaml`與`freedom-skill.yaml`另固定使用`freedom-yaml-json-v1`：UTF-8無BOM、單一YAML 1.2 document、JSON schema scalar resolution且parse結果只能是JSON data model；在schema前拒絕directives、explicit/custom tags、anchors、aliases、merge key、duplicate key、complex／non-string mapping key、non-finite／非JSON number、tab indentation及第二份document／trailing content。兩套loader要共用`yes/no`、timestamp-like scalar、leading-zero／sexagesimal number、`<<` merge、anchor/alias、tag、duplicate key、multi-document與BOM負例，不能靠YAML 1.1／library default猜語意。
   - CI 必須註冊 `nonnegative-int64-decimal-string`、`positive-int64-decimal-string`、`signed-int64-decimal-string`（各自驗上下界與正負限制）、`spdx-expression`、`iana-time-zone`及`freedom-semver-range-v1` custom format；時區須存在於 contract release 鎖定的 IANA tzdb 版本。`freedom-semver-range-v1`只接受exact完整SemVer 2.0.0，或以一個ASCII space連接的`=|<|<=|>|>=`＋完整SemVer comparator；OR delimiter只能是exact ` || `。Bare partial、`v` prefix、latest、wildcard、caret、tilde、hyphen range、tab與其他空白都拒絕。不能因一般 validator 預設忽略未知 format 就宣告通過。
   - OpenAPI／JSON Schema 的 `x-uniqueBy`與`x-uniqueFields`是required contract assertions，不是註解；前者拒絕指定單一欄位重複（目前包括`SettlementMandate.bounds[].bound_id`、SOW `deliverables[].deliverable_id`／`milestones[].milestone_id`、`CreateEngagementAllocationPlanRequest.entries[].entry_id`、skill `requirements.dependencies[].package_id`、`profession_bindings[].profession_id`與`agent_tasks[].task_type`），後者要求所列每一欄各自唯一。`ProjectStatusAttestation.statement.artifacts`的`artifact_id`、`release_asset_id`與`name`三欄必須各自獨立唯一，CI/server validator要為三種duplicate各跑negative fixture。標準`uniqueItems`只排除整個物件完全相同，不能取代這些檢查；exact-set比較也不得先把duplicates collapse掉。
   - `x-invariants` 也是 required contract assertion；首批 relational fixtures 至少驗 `ExecutionGrantSummary.remaining_action_count <= max_action_count`、cost cap／consumed 同幣別且 consumed 不超 cap、AllocationPlan required participants 恰好等於 entry participants，以及每位 signer 只能引用屬於自己的 entries。`dependentRequired` 只保證欄位成對出現，不能取代數值／集合／ownership 檢查。
3. 從 schema 生成 TypeScript types/client；禁止手寫第二份語意不同的型別。
4. 每個 producer/consumer repo 跑 compatibility tests。
5. Breaking change 發新 major/type；rules/config 改版發 immutable version/hash。
6. 每個 catalog event 在正式發布前必須有不可變 `dataschema` URL、可解析的 event-specific JSON Schema 與正／反例 fixture；planning URI 未 materialize 時不得由 production producer 發送。
7. Contract CI 模擬公開 `eventsequence` gap：consumer 只前移 contiguous cursor，先到的 `N+2` 必須 buffer/replay，待 `N+1` 成功後才依序 drain；不可因 `aggregateversion` 跳號而等待未發布的內部 transition。
8. Project manifest 除 JSON Schema 外必跑 GitHub與URL semantic checks：實際repo ID/full name/visibility/fork parent、stable organization allowlist、derived HTTPS／Pages URL與production release SHA；fork的YAML不得自行宣告official，且`upstream.project_id`必須存在並不得等於root `project_id`，此關係要有negative fixture。`external_systems_of_record`不可為空，`none`不得與任何真實system並存；`customer_data_mode: external_client_owned`至少要列`client_database`或`client_storage`，三種錯誤都要有negative fixture。若`dynamic_credential_storage`含`postgres_envelope_vault`，必須同時宣告PostgreSQL reference metadata與非DB的核准credential root-key backend；`none`與其他dynamic custody並存、vault搭`credential_root_key_storage: none|client_owned`、或中央平台的`stores_plaintext_credentials`非false均為negative fixtures。客戶端唯一例外是 schema 明列的 `external_client_owned`／`client_owned` scoped read token：最長 604800 秒、私有 0600 本機檔案、禁止 repo／browser／PostgreSQL 保存，且必須宣告完整 `client_credential_policy`；server/platform 類型不得援用此例外。URL必須用strict parser正規化並拒絕username/password、反斜線、encoded authority delimiter、control character與非canonical host；canonical Platform、GitHub Pages及official production origins只能由trusted registry推導，外部demo／documentation／support／issues則逐欄allowlist並在UI標示external hostname。Negative fixtures至少含self-upstream、錯誤Pages/repo、`https://trusted.example@evil.example`、反斜線／encoded-host混淆與未核准external origin。Generator／action／reusable-workflow coordinates不得來自manifest；Freedom-managed organization repo的真正merge gate由organization ruleset強制執行public中央automation repo內的required workflow，PR不能以repo-local workflow或同名check取代，中央workflow內所有外部action／generator均pin full commit SHA。外部owner的fork只能advisory呼叫公開automation，Platform不得宣稱能強制其ruleset，且它永遠不能取得official status。
   - Skill package的`human_control.never_store_chain_of_thought`必須存在且只能是`true`；缺欄或`false`都必須有negative fixture並fail closed。
   - Skill package與`lineage[].version`必須通過schema內完整SemVer 2.0.0 pattern；dependency `version_range`必須由上述mandatory custom format驗證。Positive fixtures至少含exact、comparator conjunction、explicit prerelease及OR；negative fixtures至少含`latest`、`1`、以`v`為prefix的`1.2.3`、numeric leading zero、`*`、caret、tilde、hyphen range、tab／雙空白與未明示prerelease。Publisher resolver另外拒絕同SemVer precedence但不同build metadata的ambiguous候選。
   - Skill capability manifest v1以`additionalProperties: false`拒絕未知top-level欄位；extension若可能影響execution／authority，必須升schema version並進共同publisher/installer compatibility tests，不能讓各CLI私自解讀同一signed bytes。
   - Root `freedom-skill.yaml` capability manifest必須和`SKILL.md`、實際發布的`agents/**`、`scripts/**`、`references/**`、`assets/**` regular files一起進`skill_package_digest`；外部`skill-package.manifest.json` sidecar不進self-hash。Publisher／installer對capability manifest用strict YAML profile解析，驗`capability.id == bundle_manifest.bundle_id == channel package_id`、version與source/file entry逐欄相等。Hashed `SKILL.md`另過共同安全子集：UTF-8無BOM、LF-only、exact delimiters，frontmatter以同一strict YAML profile解析且只准ordered required `name`／`description`；name須符合1–64 lowercase-hyphen grammar、無edge/consecutive hyphen，等於package ID末段及native parent dir，description為1–1024 scalar values。`allowed-tools`及其他client-specific frontmatter一律禁止；`static-skill-body-linter-v1`拒絕Claude `!` command、argument/session substitutions與任何已知auto-executing markup，只容許指向hashed package file的relative routing。所有entrypoints須符合160/100-byte portable path且存在／digest相符。Package pin另逐欄綁complete manifest JCS→`package_manifest_sha256`、manifest payload→`skill_package_digest`、manifest archive name/hash→locator/`package_archive_sha256`及download/extract file-list；bundle kind/profile錯置、frontmatter-parent/name collision、dynamic body、identity/source/missing/extra/path或URL-as-local-entrypoint全部fail closed。外部`demo_url`永不執行且仍過strict URL/SSRF policy。
   - `portable-activation.schema.json`各array上的`x-uniqueBy`至少拒絕duplicate file path、closure package ID、signature `kid`、authorization/channel minimum、revoked key/package digest與publisher key。JCS前拒絕未依contract排序：proof/policy keys依`kid`，policy/index authorizations與minimums依`channel_id`，revoked keys依`kid`，revoked packages依`(package_id,version,skill_package_digest)` tuple。Exact signer set屬artifact identity。兩套獨立publisher/installer須對同一真實Ed25519 fixture產生相同digests。Bundle path使用160-byte total／100-byte segment的ASCII profile，先拒絕反斜線、Windows device、trailing dot/space與case collision再extract。Archive mode/uid/gid/time/ACL/xattr/ADS/resource fork/special bits全部strip，`path-derived-readonly-v1`重建directories與`scripts/**`為POSIX `0555`、其他files `0444`或Windows等價ACL；script只由trusted versioned runner exact argv啟動。Mode/setuid/writable/PATH/shebang substitution都是negative fixtures。
   - Signed channel、revocation snapshot、5分鐘publisher bootstrap index與key transition固定用JCS statement＋RFC 7797 detached Ed25519 2-of-N；proof array恰兩個sorted、distinct、valid `kid`，少／多／invalid皆拒。Production publisher採無私鑰coordinator、兩個不同runtime／deploy-admin boundary的online signer各持一把non-exportable key，以及第三把offline recovery key；兩個signer各自驗append-only journal/high-water，quorum outage一律fail closed，不能降級成1-of-N。Initial policy artifact/fingerprint及exact selected `channel_id`由OOB交付；policy列出允許channel/profile/registry、base floors/checkpoints、stable repo ID、strict HTTPS endpoints及同一份固定network-fetch profile。`keyset_endpoint`只以no-query/body/credential GET取得typed signed bootstrap index；index由其issued-time active policy簽署，pin完整transition locators、rolling checkpoints/floors及**exact current channel/revocation** URI、artifact/statement digests、sequence與validity。Mutable channel/revocation indexes僅advisory。Index TTL固定300秒、transition至少提前900秒公布且每個signer驗append-only complete journal，阻止endpoint用舊prefix跨cutover replay；keyset endpoints改址、network profile改版或threshold compromise只走OOB ceremony。URL/DNS/redirect逐跳套canonical origin/path與SSRF及固定redirect/DNS/header/deadline/request/byte bounds；redirect/retry不能重置budget，exact cap可接受、超一byte或到達exclusive deadline即拒，任一project/index不得選channel、改budget或拼URL。
   - Channel/revocation sequence 1的三個previous欄皆null，其後完整簽previous statement/artifact digest與content-addressed URI；從signed rolling checkpoint到index exact current head逐一減1，最多64 links，gap/fork/cycle/過長拒絕。Revocation sets累積append-only，既有key/package tombstone不得改／漏，channel floors不得降。Key tombstone以`invalid_from`判statement time：早於它的歷史proof仍有效，等於／之後失效；normal retired/superseded要求`invalid_from=revoked_at`，compromise可回溯，若打斷必要transition則OOB rebootstrap。Channel/revocation expiry為exclusive且old-policy artifact `expires_at <= next effective_at`，防止old keys用backdated issued_at跨cutover。Index、revocation與channel三窗任一過期即fail closed。
   - Signed channel逐欄pin exact kind/profile的root/dependency packages、Plan/Contract manifests/archives與stable GitHub locators；registry snapshot避免self locator，closure digest只hashordered `{package_id,version,skill_package_digest}`。`activation_digest`固定hash八個named digests：channel artifact/statement、active keyset-chain、bootstrap-index artifact/statement、active publisher policy、revocation artifact/statement。Deterministic external lock另複製index minima及exact checkpoint pins、三窗與64-link cap；不含installer/time/host path，完整lock hash由pointer固定。Cache exact mapping固定current/history/policy/index/transition/manifest filenames與19/4位padding；session用`skills/<verified-name>`、`plan/`，不得實作自選路徑。`active.json`只作CAS/atomic launcher index，每次重驗；launcher在同一個global exclusive installer/GC lock內讀pointer、驗authority/lock/quota、原子發布綁定pointer generation/digest的lease並取得OS lease lock，再以exact pointer bytes/digest作最後比較才可暴露session。GC只保留active pointer與有效持鎖lease的transitive closure，依10 GiB cache、1 GiB free reserve、64 live leases、16 distinct marked activation records與24小時grace做admission；超額只回`cache_quota_exceeded`，不得刪marked或grace內資料。Trash、第二次root reread、crash recovery及no-link traversal都在同一鎖內。240-char preflight與actual filesystem/runtime/adapter probe fail closed。Missing/stale/truncated index、non-current head、history/revocation omission、layout差異、nondeterministic lock、失效lease、quota超限或offline無current authority都是negative fixtures；不掃cache找LKG也不自動rollback。
   - `CreateAgentRunRequest`不得接受`equipped_skill_version_refs`或自選overlay；server由immutable WorkItem推導exact domain set、驗current equip/grant/task並回傳保存，空set合法。`domain_skill_runtime_mode`只有`eligibility_and_provenance_only_v1`與`signed_isolated_overlay_v1`：前者是overlay未就緒時的fail-closed預設，不fetch/materialize/discover/execute；後者只有`BLD-05` signed artifact、exact runtime-scope QC、current publisher authority、current revocation、`runtime_roots_set_digest`與per-run isolated loading全數通過才可由server選用。既有八輸入control `activation_digest`不變；overlay另存artifact／statement／roots-set digests。任一gate失敗回`capability_unavailable`且零domain Skill execution／consequential effect。Client額外/缺漏ref、自報mode／overlay、未簽root或host/global discovery candidate都fail closed。AgentRun其餘provenance scalar/arrays仍明確null/empty，不保存chain-of-thought。
   - `domain-skill-overlay.schema.json`的`runtime_roots_set_digest`固定為`SHA-256(JCS({control_activation_digest,domain_roots}))`，其中`domain_roots`依`skill_version_ref`排序並逐項綁identity、package／archive／dependency-closure與QC digests。Proof恰有兩個不同且有效的publisher `kid`；每個新session重驗5分鐘bootstrap index、15分鐘revocation與overlay validity，並要求server-derived WorkItem refs與overlay roots exact-set相等。QC reviewer與submitter須為不同自然人；runtime admission QC不自動授予official／commercial-ready。三CLI必跑missing/extra/reordered root、digest mismatch、expired/revoked、QC mismatch/self-review、case-fold collision、host shadow、mid-run update與unsupported isolation負例。
   - Submission intake CI必須以`submission-intake.example.yaml`驗Portal／LINE／Discord／document四種create及WorkItem／OpportunityStub兩種typed target。Request不得含owner/community/raw content；server依session、grant或verified Inbox＋active ExternalIdentity推導owner。Source key＋hash及HTTP request hash都做冪等衝突檢查；confirm/reject僅owner／authorized organization operator的Portal session＋CSRF，且`If-Match`等於body version。Confirm必須逐欄比對`acknowledged_source_ref/revision/content_sha256`與saved tuple；external document endpoint offline仍可confirm，且confirm若fetch或聲稱current reachability／bytes即contract failure。未link／ambiguous identity、ack tuple不符、Platform已知access-policy revoked、wrong source-auth mode、service／Agent terminal command、target-kind change、terminal race、raw全文或credential進event/log/prompt都須zero-side-effect fail；confirm只能原子建立一個仍為draft/private的target。Document WorkItem綁exact requirement；OpportunityStub不授予Agent access，後續Project WorkItem需要文件時須明示copy requirement。Bound local Agent其後以current lease/fence回報本機exact-revision SHA-256；receipt只是Agent assertion/provenance、不取代review／A4。Unavailable／denied／missing revision／digest mismatch留下failure receipt、fail run且零 consequential effects；外部訊息永遠不是A4。
