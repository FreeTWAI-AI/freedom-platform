# 一位成員如何得到幫助，也一起創造價值

> 2026-09-19修訂；以下是設計情境，不是真實使用紀錄或已上線功能。

> 2026-09-23 進度：公開會員入口、公會技能書及 code 共創已有實作；新會員先完成定位。本輪加入本人自願實益回報，並不表示下列完整 Squad／Agent／capacity／收款情境都已實現。下方「現在與後續」保留 2026-09-20 時點，現況見 [落差盤點](../development/plan-drift-2026-09-23.md)。

## 先看見自己的問題，不先領一堆任務

他打開Portal，首頁有三個入口：「我需要幫助」「我能提供協助」「我們正在一起做」。他不必先有Agent、官職、積分或付費會員，才能提出每週整理資料很費時的問題。

他選一個範本，確認問題、期待改善、可提供的去識別樣本、自己最多能投入的時間及成果能否公開。AI可協助整理，不能替他捏造預算或保證有人回答。没有人承接，卡片會提供自助資源、縮小題目或到期結束，不由核心私下找人救火。

## 幫助者看見自己這一次會得到什麼

另一位成員剛好也需要類似模板。他看見：最多投入90分鐘，做出的工具自己也能用，需求者會提供實測。這是有限互助，不是拿XP交換錢，也不是宣稱以後一定有案子。

一位學習者加入測試與文件，承諾30分鐘。他得到可使用的模板；只有有人真的接受並預留15分鐘回饋時，卡片才寫會有真人回饋。數字只是情境例子，不代表任何人已承諾時間。

## 我們一起完成一個真實改善

三人用既有Squad記一個共同目標，各自認領清楚範圍。需求、測試、文件和程式同樣能形成贡献，不要求每个人都當開發者。系統整理進度；想同步解題就自願約一次，不開每週全員報告會。

沒有正式reviewer時仍能認領、創作與提交，介面顯示candidate及review capacity未知／不足。正式QC、official與商業標籤仍按原規則，不因一起做成東西就自動通過。

## 完成後，各自說得到什麼

完成頁問他們是否得到預期實益，可以選部分得到、沒有得到、還不確定，也能略過。可附一個成果ref，工時只需可略過的粗估，不寫長報告。Agent不能代本人按「我真的受益」。

沒回報就是未知，不扣權益，不因此拒付依法／依約應得款項，不把他追到回覆為止。作品驗收、貢獻、實益、正式QC與金流是不同事實。

## 下一位可以少走一次同樣的路

經權利人同意且符合license／可見範圍，模板與說明能給下一位重用。私人資料不跟著公開。真正目標是下一次需求更少依賴真人重教，而不是讓同一位熟手一直重複免費服務。

願意再合作的人可以提出下一個小目標、自願續組；不想繼續也不用還「人情債」。希望幫忙但這週沒有時間，可以把新供給設為零，不會被系統安排上工。

## 有付費需求才開新的服務案件

有組織需要客製導入時，另建ServiceEngagement、SOW、milestones及Squad自議allocation。原本志願者不自動承擔售後；每位加入者先同意自己的範圍與報酬條件。

預設record_only只做記錄與對帳；應付、已記錄、付款執行與已確認實收分開。要自動金流仍需原有有效mandate、當事人與Ted的exact A4等條件。任何PR、感謝或實益回報不自動產生分潤或永久ownership。

## 現在與後續

2026-09-20 已增加本機 Portal／API 與工作、合作流程的整合及瀏覽器測試，精確範圍見[版本紀錄](../releases/2026-09-20-local-core.md)；尚未對外部署、核實銀行收款或進行真人試行。實作細節見`12`、`03/04`、OpenAPI與FW-13–FW-15。首批平行觀察有限互助與作品曝光 → 商機 → 合作 → Seller 外部實收，完整架構照常建立，不把每個模組都同時變成有人維護的服務承諾。
