# SC-SPEC-01 資訊架構、角色、頁面與視覺

需求：SC-R01、R05、R07、R08、R09、R18、R33。旅程：J01～J04、J06。頁面資料與權限見 [pages.md](pages.md)。

## 目的與非目標

把現在「三區長頁」的供貨商品庫換成一個私人供應事業工作台：固定路由、側欄導覽、每頁一個清楚的工作。非目標：新品牌、新字型、新全站色盤；第二套全站導覽；營收、佣金、付款或履約介面；只有標題的「即將推出」。

## 路由

所有頁面在既有 `stores` 分頁之下，不新增全站 TabId，也不佔用舊的 `#supplier`（AI 內部商店工具）。

| 頁面 | Hash |
| --- | --- |
| 營運概覽 | `#stores/<tenant>/<instance>/supply` |
| 商品與庫存 | `…/supply/products`，可帶 `?state=offered｜not_offered｜outdated｜out_of_stock&sort=sku｜title｜available` |
| 新增商品 | `…/supply/products/new` |
| 商品詳情 | `…/supply/products/<product_id>` |
| 合作店家 | `…/supply/partners`；詳情 `…/supply/partners/<partner_id>` |
| 供貨條件與審核 | `…/supply/terms`；單筆審核 `…/supply/terms/<selection_id>` |
| 預留與訂單 | `…/supply/reservations`，可帶 `?state=reserved｜cancelled｜expired&partner=<partner_id>&product=<product_id>&from=YYYY-MM-DD&to=YYYY-MM-DD`（S2）；明細 `…/supply/reservations/<order_id>` |
| 行銷素材 | `…/supply/materials`；新增 `…/supply/materials/new`；詳情 `…/supply/materials/<material_id>`（S3） |
| 營運報表 | `…/supply/reports`，可帶 `?from=YYYY-MM-DD&to=YYYY-MM-DD`（S3；兩者合法且不超過 366 天才採用，否則用最近 30 天） |
| 設定與資料 | `…/supply/settings` |

- `<tenant>`、`<instance>`、`<product_id>`、`<partner_id>`、`<selection_id>`、`<order_id>`、`<material_id>` 都必須通過 `OpaqueId`；query 只接受上表的鍵與值，其餘一律忽略（當作沒有），不以 `replaceState` 改寫網址；畫面產生的連結一律是標準形式。
- 先切開 path 與 query，再解析；query 永遠不會被當成 tenant 或 instance。
- 未知頁名（例如 `…/supply/payments`）顯示「找不到這個頁面」與「回到營運概覽」，不自動建立任何資料。
- 舊入口：`#stores/<t>/<i>/supply` 就是概覽，書籤不變；新版開啟時 `#stores/<t>/<i>/supply-orders` 顯示營運中心的預留頁（同一事業）。launchpad 關閉時沿用既有歷史訂單頁。`#stores/supply`（商品庫清單）不變。
- 草稿、搜尋文字、分頁游標與任何 token 不進 URL。

## 版面

```
┌ 平台頂部（原品牌、全站導覽、h1＝目前頁名、頁面工具）──────────────┐
│ 事業列：事業名稱 · 純供貨／已開零售 · 切換事業 · 返回公會           │
├──────────────┬──────────────────────────────────────────────┤
│ 營運          │ 頁面內容（區段標題 h2，主要動作最多一個 primary）      │
│  營運概覽     │                                              │
│  商品與庫存   │                                              │
│  預留與訂單   │                                              │
│ 合作          │                                              │
│  合作店家     │                                              │
│  供貨條件與審核│                                              │
│ 管理          │                                              │
│  行銷素材     │                                              │
│  營運報表     │                                              │
│  設定與資料   │                                              │
└──────────────┴──────────────────────────────────────────────┘
```

- 側欄沿用公會啟動台已上線的做法（`apps/portal-web/src/modules/GuildLaunchpad.css:36,47`）：桌面固定欄 `12rem` 加 `minmax(0,1fr)`；窄螢幕改成同一份項目產生的 `<select>`（標籤「營運中心頁面」）。只有一份項目資料，兩種呈現。
- 側欄、窄螢幕選單與內容欄由共用元件 `modules/agent-commerce/hosted-ui/ConsoleShell.tsx` 產生（項目：key、名稱、分組、hash 連結；設定未完成時整組停用並說明原因）。賣家後台用同一元件，不另做第二套；路由、讀取、命令與離開保護仍由各自的頁面負責。
- `<nav aria-label="營運中心">`，目前項 `aria-current="page"`，以粗體加底線表示，不只靠顏色。
- h1 由平台頂部提供（`App.tsx:830` 改為依解析後的頁面取名）；事業名稱在事業列，不另放第二個 h1。換頁時焦點移到內容區的第一個 h2。
- 預留與訂單只在 owner 讀取成功後出現；行銷素材與營運報表需要 `store:write`；只有 `store:read` 時側欄只剩概覽與設定，並在概覽說明原因。
- 頁面工具使用新的頁面 ID `supplier-console`（登錄於 `modules/development/pages.ts` 與 `apps/portal-web/src/page-help.ts`）；新手引導沿用 `stores` 的「商店導覽尚未完成審核」停用原因，不保留右側空欄（`DESIGN.md` 第 15、17 行）。

## 各頁視覺重點

- **概覽**：第一屏是四個指標與待辦，不放歡迎大圖。指標卡在 ≥1280px 一列四張、768px 兩列、390／320px 單欄；每張卡固定為「名稱、數字或『無法取得』、一句定義、資料時間、查看清單」，同列同高。沒有趨勢箭頭、沒有每張卡一個裝飾圖示。待辦列表每列：對象（商品／店家）、原因、下一步按鈕（次級尺寸）。
- **商品與庫存**：桌面是表格（縮圖 48px、名稱與 SKU、供貨單價、庫存／已預留／可用、供貨版本狀態、合作），手機改為卡片；數字欄右對齊、等寬數字。頂部只有一個 primary「新增商品」。
- **商品詳情**：完整頁面，分區標題固定為「內容、照片、庫存、供貨條件、供貨版本、合作」；每區有自己的保存按鈕與狀態列，不使用整頁一個大表單。
- **審核頁**：左右（桌面）／上下（手機）對照「賣家提案」與「目前供貨版本」，差異以文字標示（例如「供貨條件已在公開後修改」），同意／不同意為同一列兩個次級按鈕，撤回同意另需確認對話框。
- **預留**：頁首固定法律語意說明；每筆以店家名稱、建立時間、到期或終態、行項小計呈現；狀態以文字＋既有 badge，不只顏色。

## 狀態語言

沿用計畫 7.2 的六種狀態，畫面文字以既有字串為優先（多數已在 `HostedSupplyCatalog.tsx`、`HostedDistribution.tsx`）：

| 狀態 | 畫面 |
| --- | --- |
| 無資料 | 「還沒有商品。新增商品後可設定供貨條件。」＋「新增商品」 |
| 無權限 | 說明缺少哪個能力與可找誰；不先讀資料再隱藏 |
| 讀取失敗／過期 | 「暫時無法讀取…，已保存的內容不會因此改變。」＋重試；數字標「未更新（最後成功 hh:mm）」 |
| 已保存但讀回失敗 | 保留「已保存」通知，數字標未更新，寫入暫停到重讀成功 |
| 結果不確定 | 「尚未確認原操作的結果，請按『重試』確認。」；整個營運中心的寫入鎖定，只能重試原操作或讀取 |
| 版本衝突 | 「資料剛剛被更新。你的修改還在，請確認後再套用。」並並列最新值 |

## 可存取性與裝置

- 所有動作是 `<button>` 或 `<a>`；表格列以第一欄的連結進入詳情，不靠整列點擊。
- 對話框用原生 `<dialog>`（`ShareLauncher.tsx` 的模式）：開啟時焦點進入、Esc 關閉、關閉後焦點回到開啟它的按鈕。
- 寫入或讀取期間停用的控制項：完成後焦點回到原控制項；原控制項消失或仍停用時，移到所在區塊的標題（沒有區塊時是頁面 h2），結果不確定時移到「重試」。只在焦點因此落到頁面本身時才移動，成員自己移開的焦點不變。
- 正文 ≥14px、手機表單輸入 16px、觸控目標 ≥44px；列內與工具列動作使用次級尺寸，桌面不把按鈕撐成整列寬。`.stack` 是直向 flex，裸按鈕會變全寬，按鈕要包在 `div.actions`。
- 淺色主題的全域 `.badge` 權重高於模組顏色（實測需看計算後顏色）。
- 只用 `DESIGN.md` 與既有 CSS 變數，不新增顏色、圓角、陰影或字級。

## 視覺驗收

- 核心頁（概覽、商品清單、商品詳情、審核、預留、設定）在淺色主題截圖 1440／1280／768／390／320。
- 概覽、商品清單、商品詳情另在夜航、敘生、引導龍、AI 姐姐四種外觀截 1440 與 390。
- 兩個未改動的公會頁做外觀回歸（例如「商品品質與供應公會」與一個非供貨公會）。
- 每張截圖檢查：溢出、遮擋（含右下訊息泡泡）、按鈕尺寸、焦點框、品牌比例、空狀態與錯誤狀態。截圖只存 repo 相對的 `test-results/`。
- 自動檢查在 `SC-E2E-40`（`tests/e2e/supplier-console-visual.spec.ts`）：溢出、導覽形式與選單尺寸、按鈕高度與寬度、概覽卡片同列等高、正文字級、品牌比例、標題與標籤對比。遮擋與整體觀感仍需看截圖。
