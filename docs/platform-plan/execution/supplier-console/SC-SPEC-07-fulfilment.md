# SC-SPEC-07 履約、寄件與退回頁面（v1.1 補充）

依據：《Freedom Supplier Console v1.1 物流、履約與售後補充計畫》（2026-10-15，隨 Commerce 規劃包提供，見 [sources.md](sources.md)）。需求：SC-L01～SC-L18。驗收：SC-LAT01～SC-LAT24。里程碑：Commerce C2。全部 planned／`not_run`。

## 目的與非目標

- 定義 SL-01～SL-05 五個頁面在營運中心裡的位置、操作、權限、狀態、未知結果與反例，以及和賣家端 E 頁面的對應。
- 原 v1.0 的 SC-R01～40、AT-01～48 與 R1 範圍不變。Supplier R1 通過不代表物流完成；Commerce C2 也不能只引用 R1 的通過就宣稱能代出貨。兩者各自驗收，共用同一份資料與領域服務。
- 非目標：第二套訂單、庫存、登入或物流後台；平台代收款、分帳或錢包；沒有開通的物流服務、COD、冷鏈、跨境的假按鈕。
- 本文件不定義型別、資料表或 migration。ShippingProfile、ShipFromLocation、ProductShippingAttributes、FulfillmentAgreement、FulfillmentOrder、Shipment、TrackingEvent、ReturnInspection 與費用紀錄等領域名稱以 Commerce 的 EC-SPEC03／05／06 為準；這裡只在頁面需要時引用。
- 本文件不授權寄件、建立物流單、扣款、開立發票、部署或接觸正式客戶。

## 2. 在營運中心的位置

SL 頁面放進既有的側欄資料清單（SC-SPEC-01），不另建需要重新登入的物流後台。頁面實作並能讀到真實資料後才加入導覽；在那之前這些路徑一律顯示「找不到這個頁面」，不放「即將推出」。

| 群組 | 頁面 | 預計路徑（`#stores/<tenant>/<instance>/supply/…`） | 出現條件 |
| --- | --- | --- | --- |
| 營運 | SL-02 出貨工作台 | `fulfilment`；任務 `fulfilment/<fulfillment_order_id>` | 有被指派的履約任務讀取權 |
| 營運 | SL-03 包裹與託運單 | `shipments/<shipment_id>`（從任務進入，不另列導覽） | 該包裹屬於本人被指派的任務 |
| 營運 | SL-04 例外與退回 | `exceptions`；退回檢驗 `returns/<return_id>` | 同 SL-02 |
| 管理 | SL-01 履約與寄件設定 | `fulfilment-settings` | 讀取：`store:read` 以上；修改：EC-SPEC05 定義的履約設定能力 |
| 管理 | SL-05 費用與交易文件 | `fees` | EC-SPEC06 定義的對帳讀取能力 |

路徑名稱在實作時加入 `route.ts` 的同一份頁面清單，ID 以 Commerce 契約的穩定 ID 為準，並沿用 `OpaqueId` 檢查與「先切 path 與 query」的規則。

## 3. 頁面

### SL-01 履約與寄件設定

- **操作**：寄件地與退回地址（用途、保存期間說明）；可用物流服務（只列已核准、且本事業有權使用的帳戶與服務）；作業日、備貨時間與截單；包裝與溫層；運費設定。商品的重量、尺寸、溫層與配送限制在商品詳情（SC-05）新增「配送」分區。
- **規則**：每個欄位真的保存並有版本；寫入沿用 SC-SPEC-02 的 attempt（Idempotency-Key、If-Match、未知結果用原內容重試、412 保留草稿）。沒有核准的服務時寫明「尚未開通可用的物流服務」，不提供假選項。欄位還沒有後端時不出現、也不在畫面暫存。
- **權限**：供應事業的 owner 或被授權的履約協作者；賣家、公會長與 Agent 都不能修改（SC-LAT01）。地址只在需要的頁面出現，不進公會區塊、公開頁或分享卡片。
- **對應**：賣家端 E11（配送政策與 provider 帳戶）。
- **需求／驗收**：SC-L01、L02、L15／SC-LAT01、02、21。

### SL-02 出貨工作台

- **操作**：依「待確認、備貨中、待印單、待交寄、例外」查看本人被指派的履約任務；接受任務、回報無法履約（缺貨、延遲等），進入任務詳情。
- **資料**：與賣家端相同的 FulfillmentOrder／Shipment ID 的投影，不另造供應商訂單。只顯示被指派行項與完成這一包所需的收件資訊；不顯示整張購物車、其他供應商的行項、買家的其他資料或付款資訊。
- **權限**：每次讀寫由伺服器核對目前的 tenant、instance 與 assignment。撤回指派後，新的讀取與標籤取用一律拒絕，也不會帶出另一包的地址（SC-LAT13）。
- **狀態**：回報無法履約後，賣家得到可以處理的待辦（替代、部分取消或退款由賣家決定）；供應商畫面沒有取消整張訂單或退款的按鈕（SC-LAT06、17）。供應商已記錄的交寄事實不因賣家畫面重讀失敗而消失。
- **對應**：E05 訂單詳情、E06 出貨與包裹。
- **需求／驗收**：SC-L05、L09、L10／SC-LAT05、06、13。

### SL-03 包裹與託運單

- **操作**：選擇本事業有權使用的物流帳戶建立物流單、查詢、列印與重印同一張標籤、記錄交寄、查看貨態。
- **規則**：一個實際包裹對應一個穩定的 Shipment。建單結果不明時先查詢原結果，不換 key 重建；provider 不支援安全查詢時顯示人工核對步驟，不提供自動重送。重印不重新付費、不產生新單。標籤與地址以短效、可稽核的授權讀取，不給公開網址。列印標籤不等於交寄，也不扣實體庫存；只有交寄事實才由唯一庫存服務扣量（SC-LAT10）。拿到物流單號或 HTTP 200 不等於已交寄或已送達。
- **貨態**：由共用物流服務驗證、去重後的事件；頁面只讀。亂序事件不讓狀態倒退，合法的退回流程保留（SC-LAT11）；一張訂單多包時逐包顯示，不把部分送達說成全部完成（SC-LAT12）。指定到無權帳戶的建單被拒絕，任務不被標成成功（SC-LAT08）。
- **對應**：E06。
- **需求／驗收**：SC-L06、L07、L08／SC-LAT07～12。

### SL-04 例外與退回

- **操作**：門市或地址失效（重選或轉例外，不假成功、不重複扣費，SC-LAT14）、延遲、毀損、未取或遺失（顯示責任人與下一步，買家端不被告知已完成，SC-LAT15）。退回包裹：收到後先「待檢、不可售」，檢驗合格的數量一次回庫，不合格的分開記錄（SC-LAT16）。
- **權限**：只處理本人範圍的包裹與退回；零售退款與發票由有權的賣家在 E09／E10 處理。
- **對應**：E05、E06、E09。
- **需求／驗收**：SC-L10、L11、L14／SC-LAT14～16、20。

### SL-05 費用與交易文件

- **操作**：查看運費、供貨款明細、退款責任與差額，以及適用的交易文件。
- **規則**：應付、已核對、已支付三個狀態分開；沒有付款或銀行證據不標成已收或已付。可提供人工「已付款證據」入口（依 EC-SPEC06）。這不是平台錢包；B2B 文件不是零售發票。售後有多條待辦（退款、退件、發票）時逐條顯示，不一鍵全部結案（SC-LAT18）。
- **對應**：E09 收款／退款／對帳、E10 發票與報表。
- **需求／驗收**：SC-L12、L13／SC-LAT17～19、21。

## 4. 與 R1 頁面的接點

| R1 頁面 | v1.1 的變化 | 何時 |
| --- | --- | --- |
| SC-03 營運概覽 | 加入待處理出貨、逾期備貨、配送例外、退件待檢四個指標；沿用「同一 snapshot、`ready`／`unavailable`＋原因、失敗不顯示 0」的規則，不顯示總單數充數 | SL-02／04 上線時 |
| SC-05 商品詳情 | 新增「配送」分區（重量、尺寸、溫層、配送限制） | EC-SPEC05 欄位上線後；之前不出現 |
| SC-07 審核頁 | R1 起固定說明「同意的是這個售價與供貨版本；不代表同意代出貨，也不會取得買家收件資料。」代出貨條件（SC-L03）是另一份有版本的同意，不併入售價同意 | 說明：R1；代出貨同意：C2 |
| SC-08 預留與訂單 | 預留頁不變（預留不是成交）；付款後的履約任務在 SL-02 | — |
| SC-11 設定與資料 | 連到 SL-01；顯示物流帳戶狀態，不顯示任何秘密 | SL-01 上線時 |

SL 頁面沿用同一個 controller、單一 attempt、每位會員的記憶體登錄與 412 草稿規則（SC-SPEC-02）。外部 provider 的未知結果另依 EC-SPEC05「先查後重試」處理。

## 6. 開始條件

1. Commerce 提交 EC-SPEC03／05／06 的契約 commit 並告知 SHA。
2. 依契約的實際名稱更新本文件（路徑、ID、能力、狀態清單）。
3. 實作供應商用途的讀取投影與 SL 頁面；寫入只呼叫 Commerce 的共同命令。
4. 物流 provider 尚未開通時只擋住該服務，不凍結 R1 的供貨功能。
