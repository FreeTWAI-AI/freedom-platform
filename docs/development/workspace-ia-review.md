# 全站導覽與頁面整理

本輪修正的是會員找不到入口、技能書與投稿混淆，以及大量重複標題延後實際操作。原始自由工坊 Logo、黑／萊姆綠／電光藍主題與既有會員資料保留。

## 審查來源

- Claude CLI 實跑 `claude-opus-5-5`：success，檢查資訊結構與重複內容。
- agy CLI 實跑 `gemini-3.1-pro-high`：exit 0，檢查手機與管理介面。CLI 未提供使用者指定的 Gemini 3.8 Preview，未冒稱執行。
- 本地獨立路由審查：全部會員頁、註冊定位、管理、GitHub callback、公開技能介紹與 Agent 入口。

模型意見是審查輸入，不等同驗收。供貨、零售與行銷維持各自任務；不採用將三者合成一個業務模組的建議。

## 導覽與相容性

主要入口固定五項。其餘依「一起協作」「供貨與銷售」「管理」收合；當前頁所在組會展開。手機使用具名選單，不以橫向滑動長列藏入口。返回上一頁、直接 hash、键盤跳到主內容及選單 Esc 都須可用。

保留 `#opensource`、`#guild-workspace` 等既有網址；新書架為 `#skills`。`#community` 繼續是社群頁，提供書架入口。GitHub 連結保留當前返回頁，預設與公開技能的登入入口指向書架。每一頁仍有對應 Agent 開發指引。

## 業務邊界

本輪不更改定位存取限制、聯絡隱私、會員／公會／管理權限、GitHub 授權或真實紀錄。投稿時安裝 App、Fork 後正式升格官方技能的完整審核流程仍是後續工作；本輪的導覽更名不代表這些流程已建好。

## 驗證入口

`tests/e2e/navigation-audit.spec.ts` 驗證分組、手機操作、角色可見範圍、書架分流與鍵盤路由；既有各模組 E2E 保留真實操作。`workshop-design.spec.ts` 走查各頁桌機與手機排版。所有瀏覽器驗證先 build、使用隔離資料；不拿真人名片當公開測試素材。

部署結果與完整 SHA 以該次 GitHub checks／deployment 記錄為準；此文件不預填測試成功。
