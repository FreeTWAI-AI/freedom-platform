# AI 雙商店：MD 開店、成果歸檔與交易轉單

頁面標記：`page:supplier`、`page:retail`。本次完整改版取代原先僅增加售價差額試算的方案。

## 已確認的產品模式

同一個人可以同時使用兩個入口，不必選「供應商」或經銷角色。

- **我有東西要賣**：做自己的內部商店，商品供登入會員挑選，商店入口不公開；內部商店須自行驗證登入、接收供貨單、用自己的金流收商品成本。
- **我可以賣東西**：挑選自己的或別人的商品，自行定價、製作公開商店、推廣與客服，用自己的金流收買家款項。
- **自由工坊**：提供 MD、成果預覽及歸檔、轉單與付款狀態記錄；出貨人可以人工登記日期、物流公司及單號。平台不代收、保管、分帳或自動扣款，不接物流平台、不追蹤包裹或推定簽收。

兩頁的主流程都是「下載任務 → AI 整理與製作 → 帶回成果」，不要求填商品長表單、學 JSON 或建立 GitHub 帳號。舊商品、合作資料與唯讀客戶端保留在舊版區，不自動轉成已完成金流的新商店。

## 實作入口

- [內部 MD](../../packages/shop-agent/internal.md)、[公開 MD](../../packages/shop-agent/public.md)、[共用金流與接口章節](../../packages/shop-agent/common.md) 是可維護的原始檔。
- `modules/agent-commerce/kit.ts` 把對應 MD、共用章節、成果格式範例及實際選品資料合成一份下載檔。由 `generate-runtime-text` 內嵌，Node 與 Worker 都可提供，不在執行時讀檔。
- `CommercePanels.tsx` 提供下載、搜尋選品、成果上傳／網址讀取、預覽確認、商店卡、金鑰設定、暫停接單、訂單／付款與人工出貨登記。
- `modules/agent-commerce/`、`routes/agent-commerce.ts`、migration `048_agent_shops.sql` 保存獨立的商店、商品、選品快照、轉單及付款事件；不挪用舊版 client 的唯讀憑證。
- 頁面導覽、說明與開發指引仍保留 `supplier`／`retail` 標記，使用新的入口名稱。

## MD 的責任

MD 要教 AI 從使用者指定且已授權的來源整理商品，不掃整台電腦、不推測價格或庫存。網站要有真正能保護密鑰的後台；靜態展示或聊天分享頁本身不等於可接金流。

引導申請金流：確認所在地與商家身分 → 查最新官方資格 → 本人完成身分／銀行驗證及契約 → AI 串官方付款、通知、查詢與退款 → 測試簽章、金額、失敗、重送、逾期 → 本人授權後才正式發布。官方參考入口及查核日期列於共用 MD；不固定承諾費率或核准資格。

金流密鑰及工坊商店金鑰由本人放入商店後台的私密設定，不放 MD、前端、網址或成果檔。外部網站的真正發布、私有權限與業者帳號仍需各店本人／AI 完成；中央平台不能替外部站保證存取限制或銀行入帳。

## 成果契約與匯入

`freedom-shop/v1` 的 JSON，或含單一 JSON 區塊的 MD，限 24 KB、每次最多 50 件。圖片使用 HTTPS 網址，沒有二進位／ZIP／任意程式執行。AI 另把網站原始檔交給本人；工坊歸檔目錄與網站入口，不在工坊同源執行外部 HTML。

內部成果包含 `access=authenticated`、每件供貨價、每件運費、可供數量與出貨／退貨條件。公開成果引用已存在的 item_id，保存自主售價與銷售說明。幣別與 test/live 模式須一致。未知數量先為 0，不自動接單。

預览不寫入；本人確認後在一個交易內寫入全部內容。同一會員、同一成果雜湊重送不重複建立商店；無效選品不部分寫入。新內容是新版本／新商店，不覆寫既有交易。不得為同一庫存重複建立可售版本；要換版先暫停舊店接單，核對尚可供數量。

網址匯入只抓 `raw.githubusercontent.com` 原始 `.json`／`.md`，拒絕重新導向、帳密、query、非 HTTPS 及其他主機；限 24 KB、8 秒。CodeSandbox、聊天或其他展示頁請交成果檔，不能假裝任意網頁都能匯入。

`/api/v1/public-shops/{id}` 只回公開商店的名稱、網址、聯絡資料與模式；內部店回 404。商品目錄需完成會員權限，沒有內部網站網址或收件資料。

## 一筆交易

1. 公開店後台先建立訂單，工坊用固定選品價格計算金額並保留數量 30 分鐘；不足不建立訂單、不向買家收款。
2. 公開店使用自己的金流向買家收款。店主後台驗證業者通知、商戶、訂單、金額與幣別後，回報付款。
3. 買家已付款的轉單才對各內部店可見；不同商品提供者分單，內部店只看到自己的部分。相同外部訂單代號／付款事件重送不重複轉單或計款。
4. 內部店為該供貨單產生受保護的同源付款入口，後台決定金額；店主在工坊按「支付商品成本」後親自完成付款。
5. 內部店驗證自己的金流通知後回報成本已付。兩笔均已付、未退款，才可人工登記出貨。
6. 買家退款與成本退款是分開的事件，不會自動互相代表；退款必須對應原收款交易。平台不執行退款或補償。

每件運費計入供貨成本；公開售價須自行包含要向買家收取的費用。v1 不做折扣、跨幣別換匯、額外買家運費或部分退款。保留期外成功付款需商店自行處理退款，不自動轉單。未付款取消釋放數量；逾期保留在下一次同社群建單時釋放。已付款／已退款商品不自動回補，退貨重新可售須另核對。

## 權限與事實界線

機器 API 是 `/shop-api/v1`；90 天、單店 Bearer 金鑰，只存雜湊。新金鑰替換舊金鑰，撤銷或會員失效即拒絕。首次原文回應不進 command_receipts；相同請求重試只回 metadata，需重新產生才有新原文。瀏覽器仍保留原本 Origin／CSRF 邊界；機器無 Origin 只在此限定路徑接受，不能使用會員 Cookie。

付款證據固定標 `merchant_backend_report`，不是平台查核銀行。test/live 不能混用；不因模擬交易而取得正式金流驗收。人工出貨是 `shipper_entered`，沒有物流 webhook。個資留在公開店，由兩店建立受授權保護的交付通道；平台只保存 delivery_ref，AI 指引要求完成該通道才能正式接單。

商店可暫停接單，保留已付款訂單的處理；未付款舊保留仍可依原約定付款。訂單 API 每頁 100 筆（offset 翻頁），單張 API 可持續查已知訂單。付款 URL 只接受已歸檔內部站同源 HTTPS；點擊本身不改付款狀態。
