# 聊天分組與自動已讀

2026-10-07，依 Hao 的「像 Discord／LINE 分群組」及「點進聊天室即已讀」要求，更新現有會員聊天。這份變更隨 Draft PR #193 提交；不表示已部署、已審核或達到競品的完整功能。

## 操作

- 桌面分成聊天類別、對話列表、目前對話三個區域。類別是私訊、公會、群組、公開、通知；列表保留名稱、時間與未讀提示。
- 群組沿用現有合作小隊及成員權限。「建立群組」前往小隊頁面的既有建立流程，沒有另建一套成員資料或開放未加入的聊天室。
- 手機列表顯示分類，點進對話後使用滿版聊天：標題旁返回、訊息區佔中間、底部輸入與送出。聊天時收起全站標題、分類與控制台，返回列表即恢復。公開聊天也可返回，文字、貼圖與引用草稿留在各自的對話。
- 輸入區依 visual viewport 高度調整，以應對手機鍵盤；貼圖面板可捲動，常用控制項保留 44px。桌面 Enter 傳送、Shift+Enter 換行；手機 Enter 換行，按送出傳送。示範工作區的資料說明仍可見。
- 一般聊天入口先顯示私訊，通知鈴鐺明確開啟通知頁，重複點擊也可切回通知。通知的整批已讀保留在通知入口。

## 已讀的時機與範圍

進入對話後，訊息成功載入，且最新一則訊息真的出現在目前畫面，便自動同步已讀。正常聊天沒有「標為已讀」按鈕。

只有正在顯示的聊天室可寫入已讀：背景瀏覽器、其他聊天類別、手機對話列表、捲動查看較早訊息時，不清除尚未看到的新訊息。回到最新訊息後再自動同步。公會、小隊與公開聊天沿用原有 sequence 水位；私訊增加可選的 `through_message_id`，驗證訊息屬於該會員和指定對象的對話，再依資料庫的 `(created_at, message_id)` 穩定順序標記到該訊息。較新的到達及其他對象／群組的未讀不會一併清除。

CSRF、本人權限、撤權檢查、command idempotency 及遲到回應的 generation 邊界保留。私訊 API 的舊 `{}` body 維持相容；新版入口一律傳已顯示的訊息界線。收到成功 ACK 才更新訊息的已讀；未讀總數重新向 API 確認，不能把 replay 的原 `updated_count` 從新快照扣掉。

如果回應遺失，保留原訊息界線及 command key，顯示同步錯誤與重試入口，不默默循環重送。重試同一筆成功後，已顯示的新訊息可以使用自己的新界線同步。網路恢復與一般 GET 更新不構成重送寫入的授權。

## 訊息搜尋與返回後的已讀恢復

- 目前對話的標題旁提供「搜尋訊息」。輸入文字並搜尋，可尋找超出目前歷史分頁的訊息；結果依新到舊顯示，20 筆一頁，可明確載入更多。搜尋中的新訊息不會被當作已看到；關閉後回到原對話、焦點與草稿，再按原有畫面可見條件同步已讀。
- 私訊、公會、小隊與公開聊天各自沿用原成員權限及社群／對話範圍。`q` 為 1–100 字元；`%`、`_`、反斜線按字面搜尋。游標驗證同一對話，資料庫排序保留完整時間精度或 bigint sequence。每次搜尋 SQL 限時 1500ms；沒有新增 migration、跨聊天室搜尋或未讀寫入。
- 搜尋視窗的錯誤有明確重試，舊查詢、舊聊天室與遲到回覆不能替換目前結果。權限拒絕會清除已顯示結果；不在裝置儲存搜尋字串或訊息內容。
- 自動已讀仍在等待回覆時，手機返回列表再開啟同一對話：若舊回覆失敗，即顯示該對話的原重試入口，保留原 key／訊息界線。另一個對話不顯示這份錯誤，也不代為重送。公會／小隊使用相同恢復規則。

搜尋 API 的完整隔離 runtime 回歸為 37 pass／0 fail／0 skip；三個 Chromium 搜尋案例驗證較早頁、27 筆字面搜尋、分頁、房間隔離、草稿、未讀、網路恢復、遲到回覆與 320px／Escape 焦點。私訊返回再開、其他對象隔離及群組返回再開亦有受控遺失 ACK 案例。正式搜尋規模、索引策略與真人操作仍需持續量測。


## 右下角訊息入口與提供的貼圖

會員其他頁面的右下角顯示 60px 訊息按鈕，點擊進入原本的私訊列表；手機返回及個別對話草稿沿用現有流程。角標加總私訊、公會、小隊與世界聊天，排除通知；任何來源無法確認時顯示「?」，不假定零。只在 focus、online、已確認操作或會員資料變更後重新讀取，不新增輪詢。首頁不開啟歷史或寫入已讀；聊天、手機選單、dialog 或展開控制台時隱藏入口。

「自由工坊」貼圖包收錄 Hao 提供的 48 張原始作品；原來 4 張仍在「工坊夥伴」，ID 保持相同。可搜尋並以縮圖選擇，選取後預覽、由使用者明確傳送。回覆與文字草稿、歷史及 API DTO 沿用原有功能；圖片失敗仍顯示文字名稱。

每張有 512×512 聊天圖（WebP quality 88）及 144×144 縮圖（quality 82），保留原圖案、文字與白底，省略 EXIF。原 JPEG 共 16,262,574 bytes；48 張聊天圖加 48 張縮圖共 3,246,798 bytes，減少 80.035%。選單只載入縮圖、圖片延遲載入；資產不嵌入 JS。此為檔案與像素數改善，未量測手機解碼 CPU／記憶體。

[資產與來源雜湊](../design/freetwai-stickers-v2.json)保存 96 個輸出、512／144 尺寸、bytes、encoder 及來源 SHA；原始 JPEG 和私人路徑不提交。`scripts/compress-chat-stickers.py --sources <private-json>` 可在有 Pillow／WebP 的環境重建；私有 JSON 包含 id、label、keywords、source。凍結上限為聊天圖 96KiB、縮圖 12KiB、兩種圖合計不超過來源 25%。

新增 `133_workshop_sticker_pack.sql` 只將兩張訊息表的已知貼圖 CHECK 擴至 52 個 ID；113 及其他歷史 migration 不改寫。部署流程需先依原 operator 規則套用 126，再提供新貼圖服務；source-only PR 沒有執行 staging／正式 migration 或部署。未知 ID 仍被 schema／API／資料庫拒絕，會員權限、CSRF 及傳送速率限制不變。
