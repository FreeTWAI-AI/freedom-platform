# 聊天分組與自動已讀

2026-10-07，依 Hao 的「像 Discord／LINE 分群組」及「點進聊天室即已讀」要求，更新現有會員聊天。這份變更隨 Draft PR #193 提交；不表示已部署、已審核或達到競品的完整功能。

## 操作

- 桌面分成聊天類別、對話列表、目前對話三個區域。類別是私訊、公會、群組、公開、通知；列表保留名稱、時間與未讀提示。
- 群組沿用現有合作小隊及成員權限。「建立群組」前往小隊頁面的既有建立流程，沒有另建一套成員資料或開放未加入的聊天室。
- 手機列表顯示分類，點進對話後使用滿版聊天：標題旁返回、訊息區佔中間、底部輸入與送出。聊天時收起全站標題、分類與控制台，返回列表即恢復。公開聊天也可返回，文字、貼圖與引用草稿留在各自的對話。
- 輸入區依 visual viewport 高度調整，以應對手機鍵盤；貼圖面板可捲動，常用控制項保留 44px。桌面 Enter 傳送、Shift+Enter 換行；手機 Enter 換行，按送出傳送。示範工作區的資料說明仍可見。
- 一般聊天入口先顯示私訊，通知鈴鐺明確開啟通知頁，重複點擊也可切回通知。通知的整批已讀保留在通知入口。

## 已讀的時機與範圍

進入對話後，訊息成功載入，且最新一則訊息真的出現在目前畫面，便自動同步已讀。正常聊天沒有「標為已讀」按鈕。

只有正在顯示的聊天室可寫入已讀：背景瀏覽器、其他聊天類別、手機對話列表、捲動查看較早訊息時，不清除尚未看到的新訊息。回到最新訊息後再自動同步。公會、小隊與公開聊天沿用原有 sequence 水位；私訊增加可選的 `through_message_id`，驗證訊息屬於該會員和指定對象的對話，再依資料庫的 `(created_at, message_id)` 穩定順序標記到該訊息。較新的到達及其他對象／群組的未讀不會一併清除。

CSRF、本人權限、撤權檢查、command idempotency 及遲到回應的 generation 邊界保留。私訊 API 的舊 `{}` body 維持相容；新版入口一律傳已顯示的訊息界線。收到成功 ACK 才更新訊息的已讀；未讀總數重新向 API 確認，不能把 replay 的原 `updated_count` 從新快照扣掉。

如果回應遺失，保留原訊息界線及 command key，顯示同步錯誤與重試入口，不默默循環重送。重試同一筆成功後，已顯示的新訊息可以使用自己的新界線同步。網路恢復與一般 GET 更新不構成重送寫入的授權。
