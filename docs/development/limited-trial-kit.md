# 有限試用套件

這份文件寫下邀請前要先講清楚的任務、同意與資料範圍。對象是少數自願會員，加上兩位核心團隊以外的公會作者。範圍由維護者劃定，不是對整個社群開放，也不是把 [收尾紀錄](../platform-plan/execution/unified-foundation/closeout.md) 裡尚未邀請的真人驗收當成已經做完。

本文件不邀請任何人、不寄信、不建立帳號，也不改產品。還沒有真人結果。邀請前再對一次正式站與 [現行旗標快照](../platform-plan/execution/unified-foundation/current-state.json)。工程收尾（R20–R24 的供貨、商店、作品、活動，含活動草稿離開保護）以該收尾紀錄為準，這裡只寫參加者要走的畫面。

付款成功的賣家案例用 [第一筆真實案例包](./first-real-case-pack.md)，不要把這次的未付款預留填進那份案例範本。介面語氣沿用 [簡約會員體驗](./calm-member-experience.md)。公會怎麼分組見 [公會圖書館版面](./guild-library-layout.md)；該頁若仍寫 `npm run verify:inventory`，那是舊門檻，這次作者不必跑。

## 目的與界線

會員從 <https://freetwai.com> 用自己的正式帳號操作。還沒有帳號時，走站上既有的 Email 與密碼註冊。四條會員任務各自獨立，做完自己那一條即可。

下列限制必須在開始前告訴參加者。旗標記錄於 R23 快照 `2bd62c256185f209dd936a8d811dc3c5d3b0d051`（2026-10-12）。R24 `dcb39351` 沒有改功能旗標、migration 或會員權限。

必須先講、而且這次任務不會打開的能力：

- 沒有真實付款、結帳、退款或出貨。預留是未付款的 30 分鐘保留。
- 參加者看得到的活動日曆，是頁內「活動行事曆」列出的已公開活動。下載行事曆、候補與提醒在 `FREEDOM_EVENT_PARTICIPATION_ENABLED` 後面，這次看不到「下載行事曆 .ics」，也不要答應日曆會自動同步或 Email 一定送到。
- 通知偏好頁面本身開著。其中「Email 摘要」區塊是停用的，核取方塊文字是「未啟用／預設未訂閱」。站內預覽不會寄出 Email。
- 商店公開頁有 `<meta name="robots" content="noindex">`。商店 API 另送 `X-Robots-Tag: noindex`（部分路由為 `noindex, nofollow`）。分享網址給人可以，搜尋引擎收錄不在這次範圍。
- `release_flags.off`：`FREEDOM_COMMUNITY_DISCOVERY_ENABLED`、`FREEDOM_UNIFIED_SHARING_ENABLED`。右上角「＋分享」（無障礙名稱「分享或提交」）仍會打開「發文」「分享作品」「刊登商品」「分享開源資源」「我的內容」。「找人合作」「發起共創邀請」以及各選項的可見範圍說明，要等統一分享引導打開才出現。公開活動頁不會走出社群發現的加入流程。
- `remaining_default_off` 對應的環境變數都維持關閉：`FREEDOM_FIRST_PARTICIPATION_ENABLED`、`FREEDOM_PARTICIPATION_METRICS_ENABLED`、`FREEDOM_MEMBER_REPORTING_ENABLED`、`FREEDOM_SKILL_BOOK_STAR_GATE_ENABLED`、`FREEDOM_EVENT_PARTICIPATION_ENABLED`、`FREEDOM_SQUAD_OUTCOMES_ENABLED`、`FREEDOM_EVENT_OUTCOMES_ENABLED`。任務卡不使用首次參與、參與度量、會員檢舉、技能書星等門檻、小隊成果或活動成果。
- 私人 AI（`FREEDOM_PRIVATE_AI_ENABLED`）在快照裡 `last_operator_enabled` 為 false。
- 媒體回收在最近備份證據為關閉，自動保留未啟用。不要答應照片會被自動清掉。
- `payment_and_fulfilment` 為 false。`retail_conversion_ui` 為 false：沒有「把供貨商品庫轉成零售店」的畫面。
- 兩環境都沒有 `tenant_authority_policies` 列。轉移或恢復擁有權會得到 403 `policy_unconfigured`。這次不要做換擁有者。

正式環境這波已經開著、任務會用到的：社群搜尋、會員封鎖、訊息圖片、通知偏好、供貨／商店預留（平台開關開著，仍要擁有者自己打開）、我的內容、公會啟動台。商店照片與照片上傳在歷史啟用紀錄裡是開的；照片不是任何一張任務卡的必要步驟。

`FREEDOM_COMMUNITY_RELATIONS_ENABLED` 不在這份快照的關閉清單，也不在 R23 正式環境的開啟清單。這次試用不用它。

## 同意與資料範圍

觀察由試用維護者手寫，不是產品裡的分析管線。參與度量旗標是關的。搜尋框裡打過的字不要抄進紀錄，除非參加者自己說出卡在哪裡。

每一列要記下：任務是否完成、卡在哪裡、維護者協助次數、隔天能否接續、失敗後能否恢復、資料有沒有遺失。

不收集：螢幕錄影、密碼、私訊與聊天內容。沒有另外取得同意之前，這些都不進紀錄，也不要把聊天室對話貼進備註。

內容規則：

- 真實作品、商品或活動，只在作者本人同意時使用。
- 否則使用看得懂的練習內容，並在備註寫明是練習。
- 不製作假的銷售、評價、採用人數或付款成功。公會預覽裡的資料是合成的，不能當成有人採用。供貨預留不是成交。

退出：參加者告訴維護者後就停止，不必給理由。還沒放進公開儲存庫的筆記，依其要求刪除。去掉身分後的共同卡點，只有本人同意才保留；不同意就連那部分一起刪。已經在站上公開的商品、作品或活動，仍由本人用產品裡的「停止公開」「撤下作品分享」或「取消活動」處理；這份套件不刪帳號。公會作者已經打開的 GitHub pull request 由作者自己關閉或續做；退出試用不會刪除 commit。

誰可以讀筆記：該列的試用維護者，以及該列的參加者。儲存庫擁有者只在決定「要不要修多人都遇到的卡點」時讀取。筆記若含身分或私人內容，留在公開儲存庫外面。以後若要提交觀察，只用參與者代號，不用姓名或 Email。

隔天還在的，是已經儲存的供貨商品、商店、活動與開源作品。還沒送出的投稿草稿只活在這次登入的記憶體裡；登出或換帳號會清掉。供貨、商店、活動表單裡還沒儲存的輸入也一樣，重新整理或登出後不在。同一場登入裡切換供貨工作區，尚未儲存的輸入會留著。

## 四條會員任務卡

每張卡從 <https://freetwai.com> 開始。首頁要先打開「我的工坊」（寬螢幕可能已經展開）。主要導覽是「會員首頁」「我的內容」「職業公會」「技能書架」；社群搜尋開著時，同一列還有「搜尋社群內容」。「更多功能」裡還有分組入口。

### 甲、純供貨會員：建立並公開一個供貨商品，再開放預留

- 起點：首頁「我的供貨商品庫」，或「更多功能」→「供貨與銷售」→「我的供貨商品庫」。網址哈希 `#stores/supply`。
- 目標：建立供貨商品庫、新增一件商品、公開供貨版本，並由擁有者開放 30 分鐘預留。
- 完成時：商品出現在商品庫；畫面上出現「已公開供貨版本，同社群店主可申請選用。」；擁有者看到「已開放 30 分鐘供貨預留。」。不必有買家結帳。

沿路：

1. 還沒有商品庫時，會看到「你還沒有供貨商品庫。請從商品品質與供應公會開始供貨設定。」以及「前往商品品質與供應公會」。公會啟動台上的按鈕是「開始供貨設定」（要已是會員，且 hosted-store 可以啟動）。
2. 表單無障礙名稱「建立供貨商品庫」。欄位是「商品庫名稱」「供貨幣別」（新臺幣 TWD／美元 USD）「商品庫說明」，送出「建立供貨商品庫」。
3. 工作區有「商品」「供貨合作」「預留與訂單」。按「新增供貨商品」，填「商品名稱」「商品說明」「供貨單價」「庫存」，送出仍是「新增供貨商品」。
4. 再開「供貨條件」，「儲存供貨條件」，然後「公開供貨版本」。提示寫著：儲存的是私人草稿；公開後，同社群且有選品權限的店主才能看到介紹、供貨價與條件並申請選用。這不會發布買家可見的零售展示頁。
5. 到「預留與訂單」。標題是「供貨庫存預留」。按鈕「開放 30 分鐘預留」；成功通知「已開放 30 分鐘預留。」。同一段文字會接著寫「付款與出貨尚未啟用。」。之後按鈕變成「停止接受新預留」。

要看的卡點：

- 「只有目前業務空間擁有者可設定供貨預留；目前沒有可用的預留管理權限。」：這張卡假定參加者是該業務空間擁有者。看到這句就停，把原句記入卡點。
- 「平台目前暫停接受新預留。」：停下記錄，不要當成已經開放。
- 還有草稿時不能切預留：「還有尚未儲存的內容，請先儲存或取消編輯，再變更預留設定。」
- 離開確認：「還有尚未儲存的內容，要離開嗎？」
- 結果不明：「尚未確認原操作的結果，請按「重試」確認。」離開時是「尚未確認原操作的結果，請按「重試」確認後再離開。」
- 買家要預留，還得有一位已同意的店主發布選品並自行開放預留。那不是這張卡的完成條件。
- 清單上的「查看商品與供貨」會進到同一套商品庫。公會區塊標題「商品與供貨」另寫「不必先建立零售店」，那是給公會頁看的，會員仍走上面這條商品庫。

### 乙、店主：發布可分享的商品頁，並用商品網址分享

- 起點：首頁「我的商店」，或「供貨與銷售」→「我的商店」。哈希 `#stores`。
- 目標：發布展示頁，讓未登入的人打開商品網址，並把該網址交給另一個人（或先記在試用筆記）。
- 完成時：已發布；登出後商品網址打得開；頁上有「商品分享連結」，連結指向同一個商品路徑；頁面仍說明尚未付款、不會安排出貨。開放預留是另一步，這張卡不必做。

沿路：

1. 空白時：「你還沒有商店。」以及「前往電商與銷售公會建立」。公會上的按鈕是「建立我的商店」；已有商店則是「進入我的商店」。
2. 設定欄位：「商店名稱」「品牌（選填）」「商店網址」「商店介紹」。新店另有「幣別」（新臺幣 TWD／美元 USD），提示「建立後不能更改。」網址前綴是 `/shops/`，說明是「3–40 個小寫英文字母、數字或連字號，以英文字母開頭；第一次發布後不能再改。」送出「建立商店」；之後改資料是「儲存商店資料」。
3. 「新增商品」後可「編輯」「儲存」「移除」。移除前會確認，並說明已發布的展示頁要重新發布才更新。至少要有一件商品。
4. 區段「預覽與發布」。第一次按「發布展示頁」，之後改內容按「發布更新」，不想公開按「停止公開」。尚未儲存時不能發：「還有尚未儲存的內容。請先儲存商店資料與商品，再發布或停止公開。」
5. 發布後的連結文字是「查看公開頁：」加上公開路徑。草稿不會改到公開頁，要再發布才會。離開確認同樣是「還有尚未儲存的內容，要離開嗎？」

商品網址不在會員編輯器裡用一顆「複製連結」按鈕。公開 HTML 由 `modules/agent-commerce/hosted/page.ts` 產生，不是入口網站上的按鈕：

- 商店頁 `/shops/{slug}` 的商品列有「查看商品」。
- 商品頁 `/shops/{slug}/products/{sku}` 有連結「登入確認預留條件」，說明「先確認是否開放，再自行選擇數量與確認預留。尚未付款，不會安排出貨。」，以及指向同一商品路徑的「商品分享連結」。
- 未發布預覽的橫幅是「這是未發布的預覽。發布後才會有可分享的商店與商品頁。」

已知限制：零售轉換介面是關的。啟動台開著時，「＋分享」裡的「刊登商品」會先提供「在站內商店刊登」與「供貨給其他店家」，下面兩項仍是商品成果上傳。不要改走首頁在啟動台關閉時才出現的「我有東西要賣」。登入後的預留按鈕是「確認預留 30 分鐘」；店主的預留訂單橫幅寫「預留，未付款／未履約」。照片可用，但改了照片仍要「發布更新」，公開頁才換版。

### 丙、開源作者：分享一個作品，再撤下並重新公開

這張卡走穩定 ID 的整件作品：投稿、管理、撤下、再次預覽並公開。它不是「發文」（送出即發布、沒有草稿），不是公會的 `WorksBlock`（那是下面的作者改程式任務），也不是按鈕「發布作品」。

- 起點：首頁「開源投稿」，或「更多功能」→「創作與合作」→「開源投稿」（`#opensource`），或「＋分享」→「分享開源資源」。
- 目標：公開一份作品，隔一段時間回來撤下，再重新公開。
- 完成時：出現「你的工具已分享！」；複製的連結打得開；從「管理這份作品」或「我的內容」回得去；撤下後舊公開連結不再打開該分享，狀態是「已撤下分享・僅本人可見」；再走「重新預覽並公開」並重新同意後，新連結打得開。收尾紀錄的工程實測包含撤下後舊連結 404；第三方快取不在這次保證內。

沿路：

1. 表單標題「投稿你的開源工具」。欄位「GitHub 專案網址」（公開可讀的 GitHub 專案）、「作品名稱」、「一句話介紹」、「我與作品的關係」（原作者／維護者／貢獻者／推薦／整理者；這是自行聲明，不是身分驗證）。
2. 「預覽投稿」不會公開。預覽標題「確認這樣分享，好嗎？」。勾選「我同意公開這份作品介紹與來源關係」，再按「確認並公開」。若是已存草稿重試，按鈕文字是「重試公開投稿」。
3. 成功後有「複製作品連結」與「管理這份作品」（`#opensource?project={id}`）。
4. 回來可走「我的內容」（`#my-content`；`FREEDOM_PERSONAL_CONTENT_ENABLED` 在這份快照是開的）。種類顯示「技能投稿」，動作「管理作品」。
5. 作品卡狀態會是「已登錄作品」「已公開社群技能書」或「已撤下分享・僅本人可見」。「編輯作品介紹」的欄位是「作品名稱」「這個作品可以做什麼」「如何開始使用」「展示網址（選填）」，送出「儲存作品介紹」。
6. 「撤下作品分享」後要勾「我了解這件作品的所有分享版本都會撤下」，再按「確認撤下作品分享」，或按「保留分享」。說明會寫公開頁、圖片、技能書架、會員目錄與舊連結會關；GitHub 儲存庫、別人已保存的副本，以及另行收錄的公會技能書不受影響；內容留在作者帳號。通知：「已撤下分享；介紹與歷史內容仍保留在你的帳號。」
7. 撤下後主按鈕變成「重新預覽並公開」。要再預覽並重新同意。編輯撤下中的作品時，提示是「修改僅本人可見；重新預覽並公開前，不會恢復分享。」分享中則是「儲存會更新目前分享中的介紹。若要先保留私人修改，請先撤下分享。」
8. 公開失敗留下的私人稿在「繼續未公開的草稿」。預覽本身不是公開。

已知限制：投稿草稿只在目前登入階段的記憶體。登出後要從已儲存的作品或「我的內容」接，接不到未送出的預覽。真實儲存庫只在作者同意時使用；選「推薦／整理者」仍要有權分享這份介紹。同一張卡上還看得到「更新 GitHub 版本」「為作品準備行銷」「核對 GitHub 管理權」「製作技能書」，都不是完成條件。統一分享的引導選項是關的。

### 丁、活動主辦：建立、分享、修改或取消，並碰到離開保護

- 起點：首頁「社群活動」，或「更多功能」→「社群參與」→「社群活動」（`#events`）。「我的內容」裡也可能看到「建立活動」。
- 目標：送出一場活動；在待審核時改一版或取消；若已核准，再分享專頁。過程中要故意帶著未儲存文字離開一次。
- 完成時：卡片在「待審核活動」（狀態「待審核」），或核准後出現在「即將舉辦」（尚未開始的公開活動狀態是「開放報名」）。待審核時做過「編輯草稿」＋「儲存修改」，或按了「取消活動」。已核准則另外完成分享。離開保護有出現確認句；沒有出現就算這張卡失敗，記入卡點。

沿路：

1. 「＋ 提交活動」，表單標題「提交活動」。欄位含「活動名稱」「活動類型」（線上讀書會／聚會／公會技能交流／其他活動）「活動說明」「開始時間」「結束時間」（提示寫目前裝置時區）「形式」（線上／實體／線上與實體）、地點、「線上參與連結」「人數上限」「主辦公會」「參與範圍」。
2. 參與範圍：「僅主辦公會成員」只在公會技能交流出現；其餘為「僅自由工坊會員」「公開頁面，須會員分享連結報名；線上資料寄 Email」「完全公開，所有人可直接查看與報名」。選了推薦連結時，提示是「海報、影片與活動說明都會公開。請勿在這些內容中放入線上參與連結或 QR 碼。」
3. 「送出前預覽活動」的提示是內容尚未公開，送出後仍需審核。送出按鈕「送出審核」。通知：「活動已送出審核，核准後開放報名。」
4. 待審核且還沒開始，才有「編輯草稿」。儲存後通知「活動已更新，仍待審核。」。已公開的活動可以取消，不能在原卡上改內容。自己的待審核或已公開活動有「取消活動」，通知「活動已取消。」。「我的內容」的取消動作也叫「取消活動」。
5. 「分享活動」只在已公開且未結束時出現。瀏覽器若提供系統分享，成功時通知是「已開啟分享。」；沒有系統分享、或系統分享失敗後改走剪貼簿，成功時是「活動專頁連結已複製，分享碼已包含在連結中。」；整段失敗時是「連結未能複製，請從下方欄位複製。」。展開的欄位叫「分享連結」，旁邊「複製連結」成功時是「活動專頁連結已複製。」，失敗時是「請選取上方連結手動複製。」。另有「活動專頁」（`#events/{id}`）。
6. 審核者：線上是「會員與社群營運公會」的公會長，實體與混合是「活動與空間公會」的公會長，公會技能交流是所選主辦公會的公會長；平台管理員也可以審。實習成員會看到「實習成員可以閱讀公會內容、在公會聊天室聊天；請會長把你設為正式成員後再發布或編輯。」志工不能自己核准，除非本來就有審核權。等待記入卡點。若試用設計要求一定要測到分享，邀請前就講明需要一位既有審核者，那一次幫忙算進「維護者協助次數」。不要請維護者按一個產品裡沒有的捷徑。

離開保護（活動頁向殼層登記）：

- 正在儲存：「正在處理活動，請等候完成後再離開。」並擋住離開。
- 上次結果不明：「尚未確認原操作的結果，請先重試原操作後再離開。」
- 有未儲存變更時，確認句是「活動有尚未儲存的內容。要捨棄變更並離開嗎？」
- 有未儲存內容、正在處理、或結果不明時，關閉分頁也會先問。

已知限制：頁內「活動行事曆」只列出目前載入的已公開活動，可翻上個月／下個月，不是訂閱日曆。「候補、行事曆與提醒」和「下載行事曆 .ics」要等活動參與旗標打開才渲染。活動成果與小隊成果是關的。「我要參加」「取消報名」是參加者的按鈕，不是主辦這張卡的完成條件。未送出的活動文字只在目前瀏覽器工作階段；已經送審的活動會留在伺服器。

## 兩張公會作者任務卡

兩位作者各自從 [FreeTWAI-AI/freedom-platform](https://github.com/FreeTWAI-AI/freedom-platform) 的乾淨 clone 開始，在自己的目錄改一個已經審查過的區塊。說明見 [公會呈現](../../packages/guild-presentation/README.md)、[供貨公會](../../modules/guild-supply/README.md)、[開源公會](../../modules/guild-open-source/README.md)。Node 需 `>=24`。

在該 clone 的儲存庫根目錄：

```sh
npm ci
npx playwright install chromium
npm run guild:preview
npm run guild:check
npm run guild:test -- modules/guild-supply
```

第二位把最後一行的目錄換成 `modules/guild-open-source`。`npm ci` 不會下載 Playwright 瀏覽器；緊接著的 `npx playwright install chromium` 用這份儲存庫鎖定的 Playwright 版本安裝隨附的 Chromium。在 Linux 上，若瀏覽器因缺少系統程式庫而無法啟動，用同一個鎖定版本自己的輔助指令安裝：`npx playwright install-deps chromium`（需要系統管理員權限／sudo）；也可以一步完成：`npx playwright install --with-deps chromium`。說明見 [Playwright 瀏覽器](https://playwright.dev/docs/browsers)。`guild:preview` 會先產生區塊再啟動 Vite，位址是 `http://127.0.0.1:4487`，資料是合成的，不連正式 API 或資料庫。檔案監控配額不夠時改跑 `GUILD_PREVIEW_POLL=1 npm run guild:preview`。預覽裡的按鈕只在本機顯示「預覽導向」或「預覽啟動」，不會對正式站建立資料。跑 `guild:test` 之前必須先停止 `guild:preview`（Ctrl+C）。兩者都綁定 `127.0.0.1:4487`，公會 Playwright 設定會自己啟動伺服器，而且 `reuseExistingServer` 是 `false`，不會沿用已經在聽的預覽。`guild:check` 是產生器 `--check` 加上 `tests/runtime/guild-blocks.test.ts`，不需要 PostgreSQL。`guild:test` 會建置預覽再跑 Playwright；`--` 後面的路徑會傳給 Playwright。

有用的修改，是只在那一個 tsx 裡改看得到的文案或版面，保留檔案開頭那串已凍結的 import，也不要新增 API 呼叫。不要手改產生的 registry、`freedom.module.json`、契約、SDK、spec、測試、中央殼層（`App.tsx`、`GuildLaunchpad.tsx`）、inventory，或另一位作者的檔案。公會 README 寫日常修改含元件與 spec；改 spec 會離開下面的快速 CI。這次試用要看的是快速路徑，所以只改那一個 tsx。

訪客狀態的文字是「登入後可查看自己的…；公會公開頁不會顯示私人資料。」，此時沒有操作按鈕。

### 作者一：`modules/guild-supply/CatalogBlock.tsx`

區塊標題是「商品與供貨」。開頭 import 必須與 [guild-presentation-profile.mjs](../../packages/contribution-tools/guild-presentation-profile.mjs) 裡 `GUILD_PRESENTATION_IMPORTS` 的供貨條目完全相同（React、`MyStoresPageSchema`、`useGuildRead`／`GuildBlockProps`、`GuildBlockState`，含結尾空行）。

### 什麼算快速 CI

對照 [select-affected-jobs.mjs](../../scripts/ci/select-affected-jobs.mjs) 的 `decideGuildPresentationProfile`，以及上面的 `guildPresentationImportsProven`。

快速路徑同時要：

- 事件是 `pull_request`。推上 `main` 或 `merge_group` 一律完整 CI；作者用 pull request。
- 每個變更都是原地修改（git 狀態 `M`）。新增、改名、刪除會得到 `guild_change_unproven`，改走完整 CI。
- 變更路徑只能是這兩個已審查檔案：`modules/guild-supply/CatalogBlock.tsx`、`modules/guild-open-source/WorksBlock.tsx`。只改其中一個，或兩個都改、且沒有其他路徑，都可以留在公會路徑。多一個別的檔案（含 spec、README、`freedom.module.json`、產生的 registry、契約、測試、API、中央殼層）就是 `outside_guild_presentation`，再落到完整 CI。spec 單獨多出來的路徑也不在文件允許清單，理由會是 `not_docs_allowlist`。
- 檔案以凍結前綴開頭，前綴之後的程式、註解與字串都不能出現英文單字 `import`、`require`、`eval`、`Function`、`Worker`、`SharedWorker`、`constructor`、`from`。中文可以改。註解裡寫了英文 `from` 或 `constructor`，理由是 `guild_source_dependencies_unproven`，改走完整 CI。
- 兩邊的 descriptor 圖相同，該檔只有一個與葉子相符的擁有者，沒有新檔案。

選到時的工作是：typecheck、portal-build、guild-registration、公會 runtime（五個檔）、殼層整合 browser（三個檔）、guild-preview（兩個檔）、static-worker。完整 runtime 與完整 browser 不會被選上。source-integrity、CodeQL 與審查仍會跑。

歷史對照只說明路徑存在過：[#467](https://github.com/FreeTWAI-AI/freedom-platform/pull/467) 只改了 `CatalogBlock.tsx`，必要 Verify 388 秒（公會 runtime 38、殼層整合 browser 15、預覽 3，以及 static-worker）。那是 AI 協作的紀錄，不是非核心真人的結果，也不保證下一次的時間。目前組織規則安裝的 PR Verify workflow pin 是 `14f82aa2`。作者不要重寫 inventory。若工具要求去改中央殼層，停下來記入觀察；這條路徑不需要改殼層。

要記下：有沒有碰到中央殼層、inventory，或找核心作者；GitHub Actions 實際花了多久；哪一則錯誤讓人看不懂。
