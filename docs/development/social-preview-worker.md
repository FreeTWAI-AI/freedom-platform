# Social preview on the main Worker

The existing explicit `FREEDOM_SOCIAL_THUMBNAIL_ENABLED=true` installation also serves original `POST /api/v1/social-posts` automatic previews through the genuine social-thumbnail service. It requires MEDIA (put/get/head/delete), IMAGES, and the separate database-owned community.social-thumbnail persistence policy with revision and retained quota. Defaults remain disabled; a missing required binding refuses the request before preview fetch. No additional Worker binding or provider secret is introduced.

`tests/worker/social-preview-assets.test.ts` runs the canonical ordinary Wrangler bundle in native local workerd with restricted PostgreSQL, native local R2 and Miniflare's low-fidelity IMAGES emulator. Its synthetic HTTPS outbound handler supplies oEmbed metadata and PNG bytes; the original fetch checker and normalizer produce WebP before original post, thumbnail pointer and receipt publication. It verifies original DTO/URLs, public cache behavior, immutable-byte SHA, no-refetch receipt replay, policy refusal, missing ports, no asset-to-legacy fallback, removal and policy-write denial. Private-literal redirects and oversized images preserve original best-effort metadata-only posts without storing images.

The original checker requires acceptable HTTPS URLs, refuses credentials and private/local literals, follows bounded manual redirects, limits bytes and deadlines, and sniffs/normalizes images. It does **not** implement DNS pinning. The companion original link-preview tests exercise deadline and malformed-image behavior. This test proves local native composition using synthetic outbound responses; remote DNS, cloud resources, real provider behavior and deployment remain untested. No paid request or cloud mutation is made.

Run the repository standard `npm run worker:dry-run`, then `TEST_DATABASE_URL=<owned isolated fp_* loopback or Unix-socket URL> npx tsx --test tests/worker/social-preview-assets.test.ts`. The fixture owns a unique database and low-privilege roles, applies all migrations and canonical runtime grants, and drops only those resources after disposing its Workers and SQL pools.
