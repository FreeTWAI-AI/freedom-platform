# Social preview on the main Worker

The existing explicit `FREEDOM_SOCIAL_THUMBNAIL_ENABLED=true` installation also serves original `POST /api/v1/social-posts` automatic previews through the genuine social-thumbnail service. It requires MEDIA (put/get/head/delete), IMAGES, and the separate database-owned community.social-thumbnail persistence policy with revision and retained quota. Defaults remain disabled; a missing required binding refuses the request before preview fetch. No additional Worker binding or provider secret is introduced.

`tests/worker/social-preview-assets.test.ts` runs the canonical ordinary Wrangler bundle in native local workerd with restricted PostgreSQL, native local R2 and Miniflare's low-fidelity IMAGES emulator. Its synthetic HTTPS outbound handler supplies oEmbed metadata and PNG bytes; the original fetch checker and normalizer produce WebP before original post, thumbnail pointer and receipt publication. It verifies original DTO/URLs, public cache behavior, immutable-byte SHA, no-refetch receipt replay, policy refusal, missing ports, no asset-to-legacy fallback, removal and policy-write denial. Private-literal redirects and oversized images preserve best-effort metadata-only posts. Untrusted public-looking hosts remain publishable without any outbound request; untrusted redirects and thumbnail hosts cannot escape the allowlist, while trusted redirects and asset namespaces still publish normalized thumbnails.

The shared checker requires acceptable HTTPS URLs, refuses credentials and private/local literals, follows bounded manual redirects, limits bytes and keeps its deadline active through DNS and response-body reads. Node pins the actual HTTPS socket to an address from an entirely public DNS answer set, retaining hostname SNI and certificate validation. Workers cannot use the same technique through its fetch-backed `https.request`; its production transport instead restricts each page, redirect and image to the fixed trusted DNS namespaces documented in [share promotion](share-promotion.md). Other HTTPS links stay shareable without automatic previews. The allowlist trusts those third-party DNS owners; it does not claim arbitrary-host DNS pinning. This native Worker test proves composition with synthetic outbound responses, not remote DNS, provider behavior or production deployment. No paid request or cloud mutation is made.

Run the repository standard `npm run worker:dry-run`, then `TEST_DATABASE_URL=<owned isolated fp_* loopback or Unix-socket URL> npx tsx --test tests/worker/social-preview-assets.test.ts`. The fixture owns a unique database and low-privilege roles, applies all migrations and canonical runtime grants, and drops only those resources after disposing its Workers and SQL pools.
