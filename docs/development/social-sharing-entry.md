# 分享與提交：單一入口

2026-10-07，Hao 回報會員不知道如何提交自己的作品，要求全面簡化操作。本輪在所有完整會員頁的標題工具列加入「＋分享」。

| 選擇 | 實際下一步 |
| --- | --- |
| 發文 | 在首頁保留當前發文草稿，或開啟社群分享的原生發文視窗 |
| 分享作品 | 前往作品與需求，直接聚焦作品標題；名稱和一句介紹是兩個必填欄位 |
| 刊登商品 | 已有成果檔時直接聚焦上傳；尚未準備時前往現有開店任務下載 |
| 分享開源資源 | 前往現有簡易投稿，直接聚焦 GitHub 專案網址 |

一般設計、影片、文章、工具作品不要求 GitHub 帳號或成果代號。作品連結可選填，既有成果引用留在進階區；社群可見分享仍需本人同意。開源資源的公開來源、原作關係、預覽與公開同意維持原流程。

入口沿用原有 Showcases、SocialZone、SimpleSkillSubmission 及商品成果預覽／匯入，不新增作品、投稿或商品資料系統。商品仍依現有 `freedom-shop/v1` 成果格式匯入；這一輪沒有把任意照片變成商品，也沒有開通付款或部署商店。

## 操作與恢復

- 選入口僅導覽、等待原控制項掛載並移動焦點。發文用原開啟按鈕；其他入口不提交表單、不自動上傳或下載。
- 懶載入與頁面資料請求使用現有入口。讀取失敗時停止等待並顯示重新載入指引；不自動重送寫入。
- 同頁重開發文保留原稿；跨頁草稿的完整恢復與瀏覽器重載持久化仍需另外設計，不能由入口推定已完成。
- 分享選單有返回、關閉與 Esc，關閉後焦點回到「＋分享」。三主題沿用品牌 token，320px 下保留完整文字與至少 44px 觸控範圍。
- 手機登入標題旁的協作工具收合，登入與密碼找回分列；public 三個角色入口保留簡短操作文字。發文長視窗保持關閉操作可見。

`tests/e2e/share-launcher.spec.ts` 驗證桌面／手機的真實提交、五個控制項入口、不自動發文或匯入、同頁草稿、失敗恢復、主題、返回與鍵盤焦點。既有 `simple-work-sharing` 測試繼續驗證作品合作、公開投稿、失敗草稿與權限。實際結果見[效能與回歸紀錄](social-platform-performance-2026-10-07.md)。真人是否自行找得到入口、操作時間與放棄率仍待維護者驗收。
