## 金流：帶著本人完成，不只是貼一個付款連結

1. 先問所在地、個人／商業身分、販售商品、收款幣別，以及是否已有金流帳號。比較可用方案前查官方最新資格與服務限制；不要承諾一定核准、特定費率或入帳時間。
2. 台灣可從綠界或藍新官方入口開始。先介紹選定方案，再帶本人進入「註冊／申請」，查看該身分需要的文件，由本人完成身分及銀行帳戶驗證、服務資料審核、同意條款及所需付款方式的申請。
3. 建立可保護密鑰的商店後台。用官方目前的 SDK／文件實作建立交易、付款完成通知、交易查詢與退款。使用託管付款頁，不自行收集卡號。只有可公開預覽的靜態頁面，還不算完成金流後台。
4. 分開測試與正式環境。成果的 mode 預設 test；付款回報也須帶 mode=test，不能混入 live。完成驗收且本人批准後，以 mode=live 的新成果建立正式商店，兩邊商品與商店 mode 必須一致。以官方測試帳號及測試交易走完成功、失敗、重複通知、錯誤簽章、錯誤金額、逾期與退款。測試通知不可送到正式工坊商店。
5. 商店後台驗證金流通知的簽章、商戶、交易號、金額、幣別及付款成功狀態；必要時以官方查詢 API 核對。網頁跳回「付款成功」或使用者按按鈕都不是收款證明。驗證成功才向工坊回報。
6. 本人核准上線後，設定正式金鑰、HTTPS 通知地址、環境與商戶設定。列出測試結果和待本人完成的部分。未核准或未驗證時，不開放正式收款。

## 回傳工坊

產生 `freedom-shop.json`（UTF-8，24 KB 內），符合本文件附的 freedom-shop/v1 結構。AI 自己生成 JSON，使用者不需手填。圖片留在本人有權使用的 HTTPS 圖片網址。可以另產生一份人看得懂的目錄 MD（只含一個 json 圍欄區塊）供上傳；不要把整份任務指令當成成果檔。

給使用者一個清楚的「下載成果」檔案。回工坊後：上傳成果 → 看預覽 → 本人確認歸檔。也支援 raw.githubusercontent.com 的原始 JSON／MD 網址；GitHub 頁面、CodeSandbox 展示頁及聊天分享頁不是原始目錄，請改交成果檔。平台不執行外部程式碼、不自動部署網站，也不抓登入後的秘密內容。

另交付完整網站原始檔與啟動／部署說明給本人保管。`website_url` 是已由本人核准的網站 HTTPS 入口；不要以示範網址冒充成果。工坊保存商店與商品資料、連到外部商店，並不把上傳的程式碼放在工坊網域執行。

相同成果重送不會新增重複商店。要改內容先和本人確認；v1 匯入是新增不可變版本，不是覆寫舊訂單。可在商店卡按「暫停接單」，停用新訂單但保留已收款訂單的處理權限；舊金鑰可另行撤銷。未知欄位、金鑰與不符合格式的欄位會被拒絕。

## 工坊交易接口 v1

完成歸檔後，本人在工坊該商店展開「連線設定」，產生 90 天有效、只屬於該店的金鑰，私下放到商店後台 `FREEDOM_SHOP_TOKEN`。只顯示一次；重建會撤銷舊金鑰。不可要求他把金鑰貼回聊天。API 基址見本文件開頭。

所有機器請求：`Authorization: Bearer $FREEDOM_SHOP_TOKEN`；POST 使用 `Content-Type: application/json`，內容不超過 32 KB。只能由伺服器呼叫，不開放瀏覽器跨站呼叫。Cookie、原本唯讀 client token 與會員身分都不能替代這個商店金鑰。401 請本人重新設定，422 修正資料，409 顯示需處理；網路失敗重送原事件／訂單代號，不另造一筆。

- `GET /connection`：取得此店 kind、mode、shop_id、currency 與公開商店的 selections（內含 selection_id、固定價格條件）。
- `GET /orders`：每頁 100 張屬於此店的訂單，可用 `?offset=100`、`?offset=200` 讀取更早資料，直到不足 100 筆。每次同步從 offset=0 開始並依訂單代號去重；已知未完成訂單另以單張 API 複查，避免新訂單擠掉舊資料。商店後台每 30–60 秒讀取並依 order_id／transfer_id 去重，不以讀取次數當成新訂單。
- `GET /orders/{order_id}`：讀取單張；內部店僅能看到自己那份轉單，沒有其他商品提供者的資料。回應包含 public_shop_id、public_website_url 與 public_shop_contact，供辨識訂單來源及設定受保護的交付通道；lines 的 snapshot.sku 對應內部店原始商品代號。
- 公開店 `POST /orders`：`{"external_id":"your-order-001","items":[{"selection_id":"UUID","quantity":1,"delivery_ref":"opaque_ref_001"}]}`。**先保留商品再向買家收款**；工坊按固定選品計算 total_minor，保留 30 分鐘。買家金流的到期時間不得晚於 expires_at。逾期成功付款需商店自行退款／聯絡，不能强迫轉單。v1 不支援超過保留期的非即時付款方式。
- 公開店 `POST /orders/{order_id}/cancel`，body `{}`：取消未付款訂單、釋放數量；已付款要走退款。
- 公開店 `POST /orders/{order_id}/payment`：記錄買家付款／全額退款。
- 內部店 `POST /orders/{order_id}/transfers/{transfer_id}/payment`：記錄商品成本付款／全額退款。
- 兩種付款 body 相同：`{"event_id":"stable-provider-event-id","type":"paid","provider":"chosen-provider","transaction_ref":"provider-transaction-id","amount_minor":50000,"currency":"TWD","mode":"test","verification":"provider_verified_by_merchant"}`。退款 type 為 `refunded`，event_id 另取穩定代號，transaction_ref 必須是原收款交易。金額以分為單位（500 元 = 50000），精確核對，不使用浮點近似。v1 只接受全額退款，部分退款留在兩店人工處理並暫停後续履約。
- 內部店 `POST /transfers/{transfer_id}/payment-link`：`{"url":"https://your-private-shop.example/pay/opaque-order"}`。必須同內部店 website_url 的 origin；此私有付款頁驗證付費店主的登入／订单權限，從後台讀工坊供貨單金額，再建立金流交易。不能信任網址帶來的金額，也不能把任意通用收款連結當成此訂單已付。

工坊只記錄 **merchant_backend_report（商店後台回報）**；金鑰驗證的是哪家店回報，不表示工坊直接向銀行核實。兩筆付款分別保存，買家退款不自動代表成本已退。工坊不代收、不抽款、不自動扣店主的錢，也不保證入帳或履約。

公開店結帳前，供貨會員必須在工坊接受該選品的 exact 售價。商店金鑰不能代為接受。未接受時建立訂單會被拒絕。買家付款回報之後，工坊才記錄供應應付與結算，狀態只有「已記錄」；這不是平台已付，也不自動扣款。賣家 margin 是實付金額減供應應付再減明示運費與稅，而且只在付款與接受都存在時出現，不能說成已收到的現金。500 元售價、360 元成本加運費、140 元差額，在那之前只是試算。

## 寄送資料與出貨

買家姓名、電話、地址留在公開店自己的後台，不放進工坊 manifest／MD／公開 repo。工坊的 delivery_ref 是不含個資的參照。公開店須建立受授權保護的交付資料入口；內部店出貨人登入後，公開店依工坊轉單核對對方店主及 transfer_id，才提供該筆最少必要收件資料。登入及商店間信任設定要由雙方確認，不把工坊長期金鑰交給另一家店。未完成安全的收件交付流程就不能開放真實交易。

兩筆付款收到後，內部店處理出貨。可回工坊該供貨單按「登記出貨」，填日期、物流公司與單號；自送／面交不用單號。工坊只顯示「出貨方已登記」，不接物流平台、不追蹤包裹、不推定簽收。公開店可從訂單 API 讀 shipment 顯示给買家，必須註明是出貨方登記。

## 歸檔與連線的先後順序

先完成可部署的測試網站與成果檔（尚無工坊商店代號時，畫面明確標示未連線，不開放結帳）→ 本人歸檔 → 取得商店代號及私密金鑰 → AI 以 /connection 取得 selection_id，啟用測試交易 → 完整驗收 → 本人核准後建立 live 成果及對應新金鑰，再驗正式設定。不要為了等 selection_id 而要求先有真實成交，也不要把測試店金鑰用於正式店。
